## 功能与使用

入口：**设置 → 通用 → 主窗口唤出位置**。

| 选项 | 行为 |
|---|---|
| 记忆上次位置（默认） | 不执行自动位置查询或移动，沿用原窗口位置 |
| 输入光标附近 | 唤出前读原编辑器光标几何；无系统光标时尝试UI Automation的文本光标或Edit输入框边界；不可用则回退鼠标 |
| 鼠标光标附近 | 在本次唤出时的鼠标位置附近显示 |

普通与紧凑模式共用，只在剪贴主窗口显示路径处理，不持续跟随鼠标/光标，不在普通窗口激活、布局切换、列表选择时不断移动。独立快速面板继续原有定位/键盘协议，托盘“设置”入口不强制执行输入定位。

优先放在锚点下方，空间不足时尝试上方、左右对齐及侧边，最后约束在锚点屏幕工作区；不跨到旧屏幕，也不覆盖任务栏。窗口大于目标工作区时缩小到可显示范围。空间无法同时容纳大窗口和输入框时，以窗口完整留在屏内为优先，不能保证始终完全避开输入内容。

跨不同DPI屏幕时按逻辑尺寸计算目标外框，并在WM_DPICHANGED的系统建议后做一次最终约束，避免重复缩放。普通/紧凑的常规尺寸快照改为逻辑尺寸，切换恢复时按当前屏幕DPI换算并限制到工作区。自动定位模式下原窗口若最大化，会先还原以便定位；记忆模式保留原最大化行为。

## 输入位置获取及边界

新模块 `src-tauri/src/main_position.rs`，在主窗口显示/抢走原编辑器焦点之前获取位置；最终移动仍在主UI线程进行，定位用SWP_NOACTIVATE，不增加焦点注入。正常唤出时主窗仍沿用原协议激活，以便用户键盘搜索。

- Win32 GetGUIThreadInfo读取原线程rcCaret并转换为屏幕坐标，原快速面板也已有同类路径；[Microsoft GUITHREADINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-guithreadinfo)。
- UI Automation尝试IUIAutomationTextPattern2的GetCaretRange，范围无矩形时仅扩展本地字符范围取得几何，不读取文字、不改变编辑器选区；最后仅对Edit控件读取边界。[Microsoft GetCaretRange](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextpattern2-getcaretrange)
- UIA只查询几何、进程/焦点/控件类型；校验前台仍是原目标、进程一致且控件未离屏。所有COM对象在后台MTA线程创建/释放，无SetFocus、AttachThreadInput、鼠标移动或模拟按键。
- UIA查询最多等待120ms，最多一个在途工作线程。超时后当前请求只使用回退结果；旧线程后来返回不会移动窗口，旧线程完成前也不继续堆积查询。120ms是UIA等待预算，不是整个应用唤出延迟承诺。
- 自绘编辑器、未启用无障碍支持的程序、管理员/权限受限输入框或提供者返回不完整几何，均可能回退鼠标；不能宣称所有应用都能得到精确插入光标。鼠标也不可用时保留原位置。

设置键 `main_position`：remember/input/mouse，强类型枚举，缺省/坏值回落remember；使用原加密settings表及草稿/保存/取消机制，schema仍v4，无新crate，仅启用现有windows crate的Accessibility/HiDpi/Ole特性。没有改变粘贴目标、掩码键、修饰键或SendInput流程。

## 人工验收

1. 默认记忆模式：手动移动主窗、隐藏再唤出，位置和普通最大化行为保持。
2. 保存鼠标模式，分别在两个屏幕不同边缘放置鼠标、聚焦编辑器后唤出；检查靠近鼠标、未超出工作区，普通/紧凑均可用。
3. 保存输入模式，隐藏主窗，在Codeg、Notepad3或其他常用输入框点击/输入，再用主窗口快捷键唤出。支持的控件应靠近输入位置，其他回退到鼠标；跨编辑器、左右/上下/负坐标屏幕分别验证。
4. 混合100%/125%/150%/200%DPI：两屏之间反复唤出、切普通/紧凑和最大化/还原，尺寸不应反复累积缩放，位置/浮窗箭头/高度正确。
5. 主窗口搜索/上下键/粘贴目标正确，关闭仍回原编辑器，不额外改变输入法；开关与“唤出首条”互不影响。设置取消不生效、保存后下次唤出生效、重启保存。
