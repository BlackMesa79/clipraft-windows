# U4 原生背景模糊可行性调查

> 2026-11-15 实施更新：用户已授权并完成 A 边缘修复、Windows Desktop Acrylic 原生验证项接入。详见 [原生模糊验证记录](U4原生模糊验证记录.md)。下方“尚未修改/实现”为此前调查档案；实际原生视觉待用户实测。

日期：2026-11-15。用户实测更喜欢 A，提供浅色窗口上的截图：渐隐暗底露出灰色矩形裁切边界，并询问能否实现背景高斯模糊。本轮仅做只读调查与记录，未修改产品、设置或用户数据。

## 截图与代码判断

当前 A 是 CSS 径向渐变，未对后方桌面做真实模糊。`ellipse at center` 使用默认尺寸，在矩形四边中点处渐变仍有非零透明度，叠加 quick / WebView 窗口裁切，符合截图中的灰色平边。可单独通过限定渐变椭圆尺寸、确保四边进入全透明区改善；尚未修改或将此修复记为已验证。

## 能力与限制

- 锁文件实际版本：Tauri 2.12.5、window-vibrancy 0.8.1，已有原生 Blur/Acrylic 路径，无需为了调查引入依赖。
- 本机 CurrentBuild 为 26200。Microsoft 的系统 backdrop 类型从 Windows 11 Build 22621 支持，TransientWindow 对应 Desktop Acrylic，适合进一步验证瞬时快速面板。
- 系统 backdrop 默认作用整个窗口范围，不能把当前 A 的 CSS 渐变当作原生模糊遮罩。柔边、透明留白和圆角区域需要独立验证，不能只打开 effect 就宣称匹配 A。
- Tauri 配置中的 radius 在 Windows 不提供角半径控制；颜色参数在 Windows 11 不生效。不能承诺仅用现有接口精确控制模糊半径、染色或渐隐范围。
- 旧 DwmEnableBlurBehindWindow 从 Windows 8 起不再产生模糊效果，不能用它调用成功作为现代 Windows 原生模糊证明。
- window-vibrancy 的 Blur 在部分 Windows 11 构建有拖动/缩放性能提示。库支持路径不等于本项目透明、鼠标穿透、非激活 quick 已实际渲染成功。
- 本地源码核对发现 Tauri set_effects 的外层返回值不直接暴露所有内部材质错误；后续必须验证实际原生渲染，不能仅检查命令返回 Ok。

## 建议的下一实施范围

先修复 A 的窗口边缘渐变裁切，再用独立原生验证窗口比较 Blur 与 Desktop Acrylic，目标为低染色、真正模糊后方内容、卡片保持清晰。重点验证不抢焦点、鼠标穿透、修饰键提交不变、连续呼出与 DPI 尺寸变化、透明边缘和角落、错误胶囊隐藏后材质清除。

原生材质与 A 的柔边不一定能通过同一层完成。先验证局部圆角模糊，再确认可否保留 A 的渐隐边缘；未验证前不默认替换 A 或将截图采集式模糊混入产品。

没有运行产品窗口或原生视觉测试，没有接管键鼠、截取桌面或修改 manual。当前仍为 A/B 半透明背景产品实现，原生模糊未接入。
