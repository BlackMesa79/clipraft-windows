## 结论

现有 Tauri 2 + Vue 3 可以继续扩展，不需要重写业务层。建议把当前“浅/深两种配色”升级为“皮肤、明暗、布局、背景材质”四个独立维度。Fluent 应作为完整皮肤，包括形状、间距、层级、控件状态、排版、图标和动效。自定义背景图是一种基础背景，可以与不同皮肤组合。

需要先确定对标基线：Fluent 2 Web 和 Windows 11 原生 WinUI 并非所有细节都相同。建议以 **Windows 11 Fluent 的桌面交互与材质** 为方向，用 Fluent 2 的设计令牌组织前端。Vue/WebView 能高度还原视觉，但“与 WinUI 每个系统控件及所有Windows版本像素完全一致”不能仅凭换CSS保证，需要原生材质能力及逐控件验证。

## 当前实现的条件与缺口

- 已有共享语义颜色、`applyTheme`、跨窗口设置事件；主窗/quick/浮窗入口分离，布局与明暗已经独立。
- `Settings.theme` 目前只有light/dark；`tokens.css` 的主要覆盖是颜色，许多圆角、间距、边框、字号和高度仍在主窗/组件CSS中写死，且存在重复覆盖。直接增加更多样式覆盖会使维护和验收复杂。
- 紧凑54px、双列248px和浮窗8px圆角属于当前几何契约；原生区域裁切另有圆角/箭头像素参数，CSS改形状时也必须同步原生轮廓。
- checkbox/select/button虽有统一样式，尚无统一的基础组件状态约定。设置共享草稿、敏感打码、焦点和粘贴协议可以继续复用。
- 当前CSP只允许应用资源、data和thumb图像，thumb协议又受剪贴板对象注册约束；背景图需要独立资源管理，不能只把任意磁盘路径塞到CSS。

## 建议的主题模型

| 维度 | 建议职责 |
|---|---|
| 皮肤skin | clipraft/fluent；控制形状、排版、阴影、控件形态、图标/动效和组件特例 |
| 明暗theme | 先保留现有light/dark及其兼容，后续可加system；每个皮肤有浅深两套语义令牌 |
| 布局layout/compact | 继续独立，保持单列/双列/紧凑的业务与键盘行为 |
| 背景background | solid/image/mica基础材质；图片资产、缩放、位置、遮罩强度等单独配置 |

建议定义带版本的ThemeDefinition，将基础色值映射为语义令牌，再由组件消费：背景层、内容层、选中/hover/pressed/focus/disabled、危险/敏感/失效、身份分组色；形状令牌包括控件/卡片/浮窗圆角、边框宽度、阴影、间距、控件高度、字体和动效时间/曲线。分组色保持稳定身份色相，由皮肤提供明度与背景规则。

多数外观由令牌完成，Fluent有不同结构时提供少量受控组件变体，例如导航项选中标识、输入框底边、开关与菜单；这些变体复用现有业务事件、原生语义和设置草稿。主窗、quick、浮窗一起消费解析后的外观，不分别硬编码。原生圆角/箭头尺寸由同一份外观几何描述派生，并保留现有定位幂等和不激活规则。

首版主题包可以是内置的受校验JSON配置，配合版本和默认值；先不开放任意CSS/脚本。原有设置缺少新增字段时回落当前外观，切换主题或材质失败时恢复上一套有效状态。避免切换外观重建历史数据或丢失滚动锚点。

## Fluent 的实现范围

1. **轮廓与层级**：按组件角色设置圆角、边框、选中标识、内容面与浮层阴影；不能把所有控件统一设成一个圆角。Fluent的形状规范本身包含不同尺寸的圆角及浮层指向形状。[官方形状规范](https://fluent2.microsoft.design/shapes)
2. **控件和排版**：统一搜索、按钮、checkbox/开关、下拉、标签、菜单、对话框及设置导航的状态矩阵，校准字号、字重、间距和点击区域。保留Tab/Space/方向键、辅助标签与高对比度。
3. **动效**：加入轻量的hover/按下、展开、切换和浮层出现过渡，并支持减少动态效果。动画不能延迟粘贴提交或改变快速面板的后端选择时序。[官方动效规范](https://fluent2.microsoft.design/motion)
4. **原生材质**：主窗可评估Mica，短暂浮层再评估Acrylic。Microsoft将Mica定义为融合桌面壁纸/主题的不透明基底，并规定多种纯色回退场景；它与“对任意背景图做实时透明模糊”不同。[Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)

Tauri具备窗口透明、阴影和特效配置路径。接入前要验证OS版本、窗口前后台、透明效果关闭、高对比度、缩放、边缘及拥有者窗口关系。Tauri官方维护的window-vibrancy列出了部分Windows版本拖动/缩放时的性能限制，因此建议先以不透明Fluent皮肤为稳定基线，再独立验证材质能力，不默认给所有窗口开启实时模糊。[Tauri窗口配置](https://v2.tauri.app/reference/config/#windowconfig)、[window-vibrancy支持与限制](https://github.com/tauri-apps/window-vibrancy#available-functions)

## 自定义背景图

建议首版只支持本地静态PNG/JPEG/WebP，导入后生成受限尺寸的显示副本，移除不需要的元数据。图片保存到应用管理的独立资源区，设置只存资产ID；沿用本地加密原则，由专用受限图像协议读取，删除/替换资产时正确回收。这样源文件被移动后依然可用，也不扩大剪贴板thumb协议的权限。

界面层按“底图 → 遮罩/色调 → 内容表面 → 浮层”组织。用户可控制cover/contain、位置和强度，浅深色分别提供遮罩默认值。历史行、搜索和设置仍由内容表面保证文字、选中态和分组标签可读。图片只铺在一个基础层，不在每条记录各自做模糊；大图先降采样，需要模糊时缓存处理结果，窗口隐藏时不继续做动画或重型处理。

背景图与Mica在基础层采用明确的优先级：选择自定义图片时使用图片基底；选择Mica时由系统材质管理基底。可以在两者上方使用Fluent控件和内容面，但不应把用户照片描述为“真正的系统Mica”。首版建议只给主窗口启用背景图；quick/只读浮窗先继承皮肤与明暗，是否继承图片由后续明确设置决定，保证正文可读。
