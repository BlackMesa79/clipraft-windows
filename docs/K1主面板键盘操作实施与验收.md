# K1 主面板键盘操作实施与验收

日期：2026-11-15。基线：S1 验收提交 `e642f46`。状态：K1键盘、紧凑/搜索切换和A方案外观均获用户实测确认，最后底部精简已获用户确认收口并授权提交。本轮按授权本地提交，未推送/重新打包；U4仅完成准备，未实现。

## 1. 已实现行为

普通、双列、紧凑三种布局共用主窗口输入入口：

| 按键 | 行为 |
|---|---|
| 裸 `↑ / ↓` | 上一条/下一条记录，首尾停止；到已加载末尾时仍先加载下一页。从搜索框进入列表并聚焦记录 |
| 裸 `Home / End` | 选中第一条/真正的最后一条并聚焦记录；End 加载完剩余分页 |
| 裸 `PageUp / PageDown` | 按列表可见行数移动，双列按可见行数乘两列计算；首尾停止，分页边界先加载再继续 |
| 裸 `← / →` | 按“全部、文本、图片、文件、链接”切换类型，首尾循环 |
| `Ctrl+↑ / Ctrl+↓` | 按“全部、未分组、用户分组显示顺序”切换视图，首尾循环 |
| `Ctrl+F` | 返回搜索框，保留搜索词 |
| `Enter / Shift+Enter / Esc` | 沿用普通粘贴、纯文本粘贴、清搜索/关闭等既有规则 |

分组切换仅改变浏览视图，不移动记录；切换类型/分组保留搜索词和另一项筛选，组合为空时明确显示空态，不放宽条件。空态可以继续按键切换。

搜索框有文字时左右键继续编辑文本，包括光标已到首尾和有选区；空搜索允许左右切类型。按上下进入列表后可直接左右切类型，Ctrl+F 返回搜索。搜索中的 Ctrl+上下可切分组，并保留搜索焦点。

原生 select（特别是紧凑分组下拉）、多行输入、分组重命名/新建、设置和热键录制、上下文菜单、删除确认与输入法组合保留原交互。新增方向键仅匹配精确修饰键；Shift/Alt/Win 的其他方向组合不误触记录或筛选。类型按钮及分组按钮获得焦点时也能用筛选键，焦点跟随当前控件选中项；工具按钮不被全局方向键劫持。

搜索框、类型按钮、分组侧栏及紧凑下拉 title 提供键位提示；不增加局部快捷键自定义或注册为系统全局快捷键。

## 2. 实现与状态边界

- `src/mainKeyboard.ts` 负责精确键位映射和环形取值，复用 MainWindow 的类型数组、后端分组顺序及既有 selectView/筛选刷新入口。
- 类型与分组 watcher 同步清空旧记录、选择、敏感详情和在途版本；连续筛选复用请求代次拒绝旧响应，不在页面加载中粘贴上一条件的旧记录。
- 切换后列表回顶部、选首项并恢复记录焦点。加载时用户已改去搜索、工具、设置或菜单的，不抢回焦点；Ctrl+F 显式取消待恢复焦点意图。
- 空结果容器可由代码聚焦，维持三布局的继续导航；不增加正常 Tab 路径中的空白停靠点。
- 保留既有普通粘贴、Shift+Enter、搜索文本 Delete/Ctrl+A、置顶快捷键和菜单/编辑优先级。未修改快速面板组件、钩子、修饰键释放、全历史会话或后端提交协议。
- 类型/分组变化后清空多选与敏感明文，即使筛选后首项仍是同 ID 也重新遵守隐私展示规则。

## 4. 用户实机验收清单

请在包含 K1 的新构建中测试；现用旧 release 不会因源码变更自动更新。可沿用独立测试目录，主对话不接管键鼠/剪贴板、不修改 manual 或真实偏好。

1. 普通、双列、紧凑分别按上下选记录、左右切类型、Ctrl+上下切分组，检查首尾循环和无结果后的继续切换。
2. 输入搜索词，有文字时左右只移动光标；上下进入列表后左右可切类型；Ctrl+F 回到原搜索词。组合筛选为零条时仍可离开空态。
3. 紧凑分组下拉获得焦点时继续按原生规则选择，提交后回到搜索；上下进入列表后使用新键位。
4. 在类型按钮和普通侧栏分组按钮上检查焦点/选中项，切分组不应移动记录。
5. 连续快速切换后按 Enter，应只粘贴当前筛选的当前记录；加载/空结果时不粘贴上一条件的记录。
6. 输入法拼写、设置录制、分组新建/重命名、菜单和删除确认期间，新方向键不得穿透；敏感原文切换筛选后重新隐藏。
7. 搜索框上下后焦点已进入列表，继续输入搜索前使用 Ctrl+F；这是本阶段明确改变的交互，测试时特别留意。
