## 待开发项目

### U2-R12-01：常规记录摘要允许自动显示两行（图一）

用户现象：记录下方有空间，长文本却只显示一行并省略；带原始换行的代码记录已经能显示两行。

只读检查已确认原因：`src/style.css` 的 `.summary` 使用 `white-space: pre; overflow: hidden; text-overflow: ellipsis`，保留原始换行但不自动折行。常规覆盖只调整字号/字重，没有改变此规则；双列已有独立两行 line-clamp。

要求：常规单列摘要自动换行，最多两行，保留合理的原始换行并处理超长连续字符/路径；超过上限再省略。来源、置顶、敏感/失效提示仍有空间，不越出记录；与当前最小行高协调。双列已有两行行为保留。紧凑模式如何分配摘要/状态需结合 54px 行高核对，不能无意改成不限高度。

验证：单行长句、原有两行代码、超过两行、长路径/连续字符、敏感与失效状态，浅深色和窄窗均检查。

### U2-R12-02：预览底部粘贴按钮改为圆角（图二）

“粘贴到原窗口”当前为直角，与整体圆角风格不一致。使用统一圆角、内边距、hover/pressed/disabled/focus 样式，沿用主题变量；不改变底部位置、粘贴行为或右上刷新按钮。只读检查：`.main-window .detail-actions .paste-primary` 未明确设置圆角。

### U2-R12-03：预览应从头部开始，排查中段显示/裁切（图三）

用户描述“文本预览像截取中间而不是开头”。图二当前实际选中的是图片，图三看起来是该图片预览中的一段列表内容。因此应记录为**预览起始位置/裁切异常待查**，不能直接断言后端文本被截去头部。

分别检查：

- 文本详情、长标题/摘要与图片预览的真实起始内容，是否因列表摘要截断被误作全文。
- 常规 `.detail-scroll` 切换记录/内容类型后是否沿用旧 scrollTop。当前主窗没有为该区域按记录设置 key 或显式复位；这是排查入口，不是已确认根因。
- 图片 contain、容器限高、overflow、滚动位置是否导致只能看到中间；原图片本身是否已经包含被裁切的截图。
- 独立浮窗 `.floating-content` 已按 item.id 设置 key，仍需覆盖同一 id 内容变化、隐藏恢复等情况。

目标：新选中记录的正文/图片从合理头部位置呈现，长内容可滚动，完整图片不被无意裁切；不通过隐藏重要内容解决问题。保留主列表自身的滚动锚点，不把详情复位与列表复位混在一起。

### U2-R12-04：紧凑列表图标区域与常规模式统一对齐（图四）

紧凑模式也使用稳定的左侧预览列，普通图标和图片缩略图在区域内水平/垂直居中，正文起点一致，视觉原则与常规模式一致。当前常规单列已有固定 80px 列，而紧凑仍是不同宽度元素直接参与 flex 排列，因此中心线和正文起点不一致。

具体列宽/图标大小结合 390px 窗宽、54px 行高调整；现有独立置顶标识、图片可读性、长摘要与敏感/失效提示不能互相挤压。此次未确认要改紧凑行高或强制复用常规全部像素尺寸。

### U2-R12-05：紧凑“分组/类型”标签间距一致（图四）

统一标签占用宽度、右侧 gap、控件/按钮起点、行高与左右内边距。不能仅统一字号；字号已为 12px/18px。当前 `.compact-groups` gap 与 `.filter-row` 的紧凑 gap 不同，是已知排查点。分组 select 和类型按钮行在浅深色/窄窗下视觉对齐。

### U2-R12-06：浮窗圆角外的白色背景（图四红框）

浮窗四角露白，需要让实际窗口轮廓和页面圆角一致，浅深色均无底色方角。**现有 `.floating-preview` 已有 border-radius:8px 和 overflow:hidden，不能简单断言少了 overflow:hidden。** 应同时检查 html/body 根背景、WebView/原生窗口背景、透明设置与系统圆角/裁切路径。截图只证明可见现象，尚未确认具体根因。

若使用透明窗口或原生圆角，须验证 Windows/DPI/阴影和实际显示路径，离屏 CSS 截图不能代替原生角落验收。不要引入激活、反复显隐或高负载渲染。

### U2-R12-07：浮窗增加箭头指向当前记录（图四）

箭头对准当前预览记录的可见行位置；浮窗在右侧时箭头在其左边，浮窗在左侧时反向。切换选中项、滚动、移动/缩放、左右回退、DPI/多屏时同步对齐，接近边缘时约束位置，避免箭头落在圆角或窗口之外。

当前原生预览只收到 id、按主窗位置定位，未收到选中行屏幕位置；实施时补充必要的几何信息，不传原文或文件载荷。选中行滚出可视区时的隐藏/定位策略需要明确，不能让箭头误指其他记录。外层箭头与内层圆角裁切要协调，避免为了修白角又裁掉箭头。

**必须保留 B-04 防护：同内容去重、定位幂等、不激活窗口、不反复 hide/show、不在快照锁内调用窗口 API。**

### U2-R12-08：所有界面滚动条统一美化

使用共享样式/主题变量统一轨道、滑块、宽度、圆角、hover 状态与对比度；覆盖历史列表、常规预览、独立浮窗、设置内容/分类、分组栏和可滚动菜单。快速面板若有滚动区域也应协调，但不改变其忽略鼠标与原键盘协议。

检查浅深色、长内容、多种 DPI、滚动条占位对布局/锚点/选中行箭头的影响；保持实际滚动、拖动滑块和可访问性，不仅做静态装饰。

### U2-R12-09：设置表单控件统一美化（图五）

统一 checkbox、radio 类选择控件、select，以及同类数字/文本输入与按钮的颜色、圆角、边框、焦点、选中、hover、disabled 和错误状态。checkbox 当前是系统默认蓝色，与青绿/蓝灰主题不协调。设置分类选择器、主题/布局/快捷键下拉和紧凑分组下拉也采用同一套视觉规范。

保留原生语义、辅助标签、Tab/Space/方向键操作和共享草稿/保存/取消/清理确认行为。当前没有 radio 的设置不新增功能，只为实际使用或通用控件准备一致样式。校验 WebView2 下原生下拉弹层与深色主题，不为样式调整引入焦点反馈或更改设置语义。

### U2-R12-10：图片类型筛选包含图片文件记录

用户现象：复制的图片文件在历史中属于 files，只选“图片”看不到，必须切到“文件”。期望“图片”也能匹配这些记录；它们仍可在“文件”类型下找到。

只读检查：`Storage::list_page` 当前对 image 直接使用 kind='image'，排除了 kind='files'；这是已确认的当前查询行为。

要求：扩大图片筛选语义，覆盖位图/截图类图片记录与图片文件记录；**不把图片文件的实际存储 kind 或 CF_HDROP 粘贴语义改成位图，不改复制/剪切及文件路径行为。** 后端查询、搜索/分组交集、分页、计数与去重保持一致，不能仅在前端当前页追加匹配。

必须覆盖单个图片文件；多文件中含图片、混合文件组、首个/非首个文件为图片的具体规则需在实现前核对并补测，本轮未单独确认这些细则。识别依据要区分真实图片属性与任意缩略图，考虑旧记录、缺失源文件、敏感记录与坏预览；不能在每次筛选时同步打开大量磁盘/网络文件。若需要新增元数据/迁移，先核对兼容策略，不在本轮执行。
