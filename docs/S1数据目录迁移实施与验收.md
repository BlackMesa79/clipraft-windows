## 1. 本阶段交付

设置新增“数据存储”分类，显示当前目录、默认/自定义状态、上次迁移保留副本，提供更改目录、恢复默认位置、预检确认和迁移并重启。

迁移确认前校验目录身份、互相包含、非空、写权限、固定磁盘与空间。确认只发送后端生成的票据，并再次检查目标；未保存的设置阻止重启，取消选择或确认条不写入待迁移任务。

启动定位文件现位于独立的 `%APPDATA%/ClipRaft/startup.json`，兼容读取原 `%APPDATA%/ClipboardM0/startup.json`。没有配置时仍使用 `%APPDATA%/ClipboardM0`，不隐式搬迁旧用户数据。正式与隔离路径入口见 `data_directory/paths.rs`。

启动时持有用户配置锁和实际数据目录锁；仅启动时短暂等待重启旧进程释放句柄。自定义目录失效或已配置目录缺少库/密钥时不会静默新建空库，提供显式选择现有数据目录的恢复入口。用户选择旧副本恢复前会提示其快照属性。

重启后先 checkpoint WAL 并关闭连接，然后检查数据库完整性与 blob 引用；生成有哈希的清单，在目标盘暂存、流式复制和逐文件校验。文件提交不覆盖已有目标文件，启动定位最后原子替换。中断按清单恢复；源变化、未知文件或目标不一致时停止并保留源，不能悄悄合并。空间预检按尚需复制量计，避免重试时错误要求再空出一份完整数据空间。

复制范围为数据库、原 DPAPI 密钥、`data` 下加密对象以及数据库迁移备份。WebView 缓存固定在用户配置根目录，不跟随自定义历史目录；诊断日志不作为历史复制。源目录保留，界面提示敏感内容可能仍在旧副本中；不移动文件记录引用的用户源文件。

主窗口预创建显式设置 `focused(false)`，与 quick/preview 一样不主动激活；实际唤出仍通过既有窗口聚焦入口。

## 2. 首版边界

- 支持本机、本账户下的本地固定磁盘目录迁移，包括实际跨卷复制；密钥算法与 DPAPI 保护不变。
- 普通非空自定义目标不合并。恢复默认时会自动把默认位置的旧应用数据移至独立保留目录，再迁入当前数据；确认页显示保留位置，无需手工删除或清空。
- 不承诺网络盘、可移除介质、同步软件并发写入或跨电脑解锁。便携发行模式与密码归档另行排期。
- 旧目录不会持续同步；界面只展示上次迁移保留位置，更早副本仍由用户自行管理。本阶段不提供自动删除副本。
- 重启后的数据迁移不提供中途取消；失败保留状态，重启可重试，或通过恢复入口显式选择现有数据。源变化或未知文件冲突时建议换新空目录。
- 常规 `CLIPBOARD_M0_DATA_DIR` 隔离环境禁用目录更改，不访问正式启动配置。显式同时设置 `CLIPRAFT_TEST_CONFIG_DIR` 才启用独立配置下的迁移测试。

## 5. 用户原生验收建议

可以先使用全新隔离数据与配置目录，不用 `.test-data/manual`。在单独终端执行：

```powershell
. ./scripts/env.ps1
$env:CLIPBOARD_M0_DATA_DIR = "$PWD/.test-data/s1-user/source"
$env:CLIPRAFT_TEST_CONFIG_DIR = "$PWD/.test-data/s1-user/profile"
npm run tauri dev
```

手动创建独立空目标文件夹，使用可丢弃样本记录验收：

1. 设置 → 数据存储核对路径；选择目录后先取消，确认历史和当前位置不变。
2. 编辑其他设置但不保存，确认迁移按钮被阻止；保存后再次确认迁移。
3. 迁移并重启，观察进度；核对历史正文、图片、分组、收藏、设置和快速面板，重启后仍用目标目录。
4. 查看旧副本提示；选择非空、相同或互相包含的目录应报错，不能覆盖文件。
5. 在全任务隔离目录中测试目标被占用、目录移走和恢复入口；仅在应用退出后操作这些测试目录，不动真实配置或 manual。
6. 切换普通、双列和紧凑模式后，存储页和确认条均能使用、长路径能换行，主窗口唤出与失焦行为无异常。

建议验收完先退出测试应用，再关闭该终端，以免隔离环境变量用于下一次真实使用。安装版目录选择器、重启进度、恢复默认冲突处理和原生焦点仍待用户确认，不因自动检查通过自动提交。
