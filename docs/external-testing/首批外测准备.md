## 邀请与节奏建议

建议第一批3～5位熟悉反馈流程的测试者，先启动冒烟，再试用2～3天；名单、发送方式和具体时间由项目负责人安排，目前无人收到测试邀请。优先覆盖不同浏览器、输入法、显示缩放和多屏。Windows 11 x64为首要验证环境；Windows 10 x64单独记为待验证兼容性，不能默认已支持所有版本。

1. 首位测试者先检查新机器能否启动、托盘/快捷键、文本/图片/单文件粘贴与打开。
2. 启动检查通过后，再扩展到其余测试者；每人记录系统版本、缩放、输入法及包编号。
3. 在合成数据上验证密码导出/恢复；有两台电脑/两个账户的志愿者单独覆盖跨机，默认目录替换只在专用测试库进行。
4. 每日按反馈模板归类：P0数据损坏/隐私泄露，P1崩溃/无法启动/主要操作失效，P2界面或非阻断问题。P0/P1先暂停扩大分发并保留复现材料，修复后用新包编号回归。
5. 首轮结束记录环境矩阵、失败项与是否进入下一批，不以“没收到反馈”代替通过。

## 构建与证据

源代码、锁文件和 `dist` 必须来自冻结提交。先执行 `npm run build`；Rust命令前加载 `scripts/env.ps1`，再使用 `cargo build --manifest-path src-tauri/Cargo.toml --target-dir .tools/external-alpha1-target --release --locked --features custom-protocol`。项目既有并发限制为2。

首次默认target构建遇到旧release exe占用，未关闭进程；改用独立target并复用构建缓存后成功，产物以独立target为准。候选打包、依赖提取与ZIP复验记录见本目录生成的 `候选包检查.json`。既有OpenSSL缺PDB的链接警告不等于构建失败。
