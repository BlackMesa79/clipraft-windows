## 3. S1：用户体验

在设置页增加“数据存储”，显示当前路径、默认/自定义状态，以及“更改目录”“恢复默认位置”。恢复默认走同一迁移流程。

首版更改目录默认带走全部已有历史、分组、收藏与设置，不提供多库合并或空库切换。由原生目录选择器选位置，面板显示最终完整路径，避免用户误解会不会自动创建子目录。

确认页展示源目录、目标目录、预计复制量、空间检查结果，主操作为“迁移并重启”，允许迁移启动前取消。耗时阶段显示进度和当前步骤；正式切换阶段不允许中途取消，但必须可从故障恢复。

首版目标为本地固定磁盘上的新目录或空目录。非空目标、同目录、互为祖先/后代、不可写或空间不足等在确认前拒绝。已存在的另一份数据不覆盖、不合并。显式测试权限与可用空间，并在实际操作时处理变化和失败，预检不能代替错误处理。

首次暂不承诺网络盘、云同步目录或可移除介质的可靠性；不能仅凭路径字符串断言识别所有同步目录。便携介质支持在后续发行阶段单独验证。

## 4. S1：路径与启动设计

将“启动定位”“持久数据”“运行缓存”分成明确职责，沿用现有模块风格，不建立杂物工具模块。

建议解析优先级：

1. 显式隔离测试目录；不读取或改写真实启动定位文件，不允许测试界面修改正式目录配置。
2. 未来显式便携模式标记：定位文件放程序旁，默认数据为相对程序目录的 `Data`，不依赖当前工作目录。
3. 安装/普通模式：固定用户配置位置保存启动定位文件，指定自定义数据根目录。
4. 无定位配置时继续使用 `%APPDATA%/ClipboardM0`，老用户不发生隐式搬迁。

启动定位文件只保存版本、路径与迁移状态等启动所需信息，不保存密钥和历史内容。新定位文件使用原子替换；自定义路径失效时展示恢复入口，不能悄悄新建空库或回退后形成两份持续写入的数据。

持久数据包含数据库、原主密钥、加密 blob、迁移备份及以后明确登记的持久资产。设置已在数据库中，不另造一份设置副本。

WebView 运行目录不作为历史数据搬迁；建议安装模式使用固定用户缓存位置，便携模式在其目录内使用独立缓存。旧版本缓存路径的过渡要单独安排，关闭使用它的进程后才能清理；不因更改目录递归复制或删除整个旧根目录。诊断日志按运行资源处理，不计入历史迁移完整性。

正式跨进程迁移前增加或复用数据目录独占机制，避免两个实例同时写同一数据根目录；锁以规范化目录身份为依据，不能只依赖全局快捷键注册失败来互斥。

## 5. S1：迁移协议与恢复

建议采用重启后的冷迁移，避免热切换 Storage、后台写入线程、缩略图协议和 WebView 目录。

1. 运行中完成目标预检，将待迁移任务可靠写入启动状态；用户确认后关闭快速面板并有序退出，停止采集、清理及其他写入，等待在途任务结束。迁移前取消时不得留下可执行的待迁移任务。
2. 下次启动在常规数据库打开、孤儿扫描、运行时线程和窗口创建之前识别任务，锁定源/目标并检查没有旧实例继续写入。
3. 使用原密钥打开源库，完成 WAL checkpoint 并确认成功，关闭全部数据库连接后复制。不能只复制运行中的 `history.db`，也不能盲删 `-wal` / `-shm`。
4. 复制到目标盘上的专用暂存目录；跨盘按复制设计，不依赖跨盘 rename。保留原数据，按应用管理文件清单处理，不跟随 junction/符号链接越过目录边界。
5. 核对复制清单、长度及哈希；用原密钥验证目标库可解密及数据库完整性，确认现存 blob 引用和文件一致。已有缺失/损坏应明确报错，不能用启动孤儿扫描掩盖迁移问题。
6. 验证通过后，在目标盘内完成暂存目录提交，再原子更新启动定位；所有状态变更记录可恢复阶段。仅在提交后才允许新目录正常启动与写入。
7. 首次从目标正常初始化成功后标记迁移完成。旧目录作为迁移保留副本，向用户明确其位置和敏感数据残留；本轮不自动删除。后续如提供清理，只清理已确认属于本次迁移的文件，不删除无关用户文件。

故障恢复必须区分提交前后：提交前源数据保持权威，可继续原目录；提交后目标为权威，不能因报错直接切回旧快照。断电后的重试先核对迁移状态和文件归属，不覆盖未知文件、不默认删除旧副本。

源目录保留副本不是持续同步备份；后续在新目录删除/到期的敏感内容不会自动从旧副本消失。界面需明确这一点，不能承诺迁移后旧位置立即不留数据。

文件型剪贴记录保存的是原始文件路径；迁移的是管理器自己的数据与预览，不搬走用户引用的源文件，也不承诺这些源文件跨电脑仍可访问。

## 6. S1：便携版边界

路径便携与密钥便携分开处理。当前主密钥由用户级 DPAPI 保护，通常需要原 Windows 登录凭据及原电脑；把程序和数据放入 U 盘不会自动获得跨电脑解密能力。

以后若要求跨电脑携带历史，再设计口令派生的主密钥封装、解锁、口令更改和恢复，并评审其密码学参数。本轮不将密钥明文存储，也不擅自替换 DPAPI。

实现依据：`src-tauri/src/platform/key.rs` 的用户级 DPAPI 调用；跨电脑解锁方案另行评审。

## 7. K1：推荐键位

| 按键 | 主面板行为 |
|---|---|
| `↑ / ↓` | 上一条 / 下一条记录，保留现有分页与循环规则 |
| `← / →` | 上一种 / 下一种类型，按当前类型行顺序首尾循环 |
| `Ctrl+↑ / Ctrl+↓` | 上一个 / 下一个分组视图，按侧栏显示顺序首尾循环 |
| `Ctrl+F` | 聚焦搜索，沿用现有行为 |
| `Tab / Shift+Tab` | 在可交互区域间移动焦点，保留原生控件语义 |
| `Enter / Esc` | 沿用当前粘贴、清搜索、关闭等上下文规则 |

分组循环包含“全部”“未分组”和用户分组，收藏维持独立开关。这里切换的是查看哪个分组，不是移动选中的记录。切换分组保留类型、搜索词及收藏条件；切换类型同样保留其他筛选，组合无结果显示空态，不偷偷放宽筛选。

推荐 `Ctrl+↑/↓` 的理由是方向对应纵向分组，只增加一个修饰键，并与裸方向键选记录区分。`Ctrl+Tab / Ctrl+Shift+Tab` 可作为用户更偏好的替代方案；首版只定一套，避免堆叠别名。左右键操作横向类型符合常见标签控件方向语义，但面板快捷操作的焦点保护仍须自行实现。

## 8. K1：焦点与状态规则

- 输入法组合中不响应筛选快捷键；设置、热键录制、菜单、分组编辑、删除确认等模式按既有优先级处理。
- 列表导航状态下裸左右键切类型。搜索框有文字时左右键始终移动光标，含选中状态与光标边界，不以“已经到边界”为理由偷切筛选；空搜索框允许左右切类型。
- 从搜索框按上下进入记录导航时，将焦点交给记录，保留搜索词；`Ctrl+F` 返回搜索。这会调整现有“上下导航后焦点仍留搜索框”的行为，用户已确认方案，实施时单独验收。
- 分组快捷键在列表与单行搜索框可用；多行输入、分组重命名、原生 select 等保留自身键盘操作。`Shift` / `Alt` / `Win` 的其他组合不能被宽松匹配成新增操作。
- 类型与分组控件获得焦点时各自支持合理的键盘操作；Tab 路径、焦点样式和选中状态需同步验证，不能靠窗口级事件抢走控件操作。
- 切换筛选后列表回到顶部并选择首项；清空旧多选、待粘贴目标和敏感明文预览。保留在前后结果中同 ID 选中的策略不加入首版。
- 复用既有筛选、分页和请求代次机制。快速连按只显示最后一次筛选结果；加载中不允许 Enter 粘贴上一筛选的旧项，空态也能继续切分组/类型。
- 普通、双列与紧凑布局共用规则；在对应控件 title/帮助处显示快捷键。首版采用固定局部快捷键，不扩展为全局注册或自定义热键录制。
- 不改变快速面板钩子、修饰键释放、V 键选择、全历史会话与提交协议；其分组筛选另行讨论。

以上应用级快捷键均为本项目交互建议，最终以用户确认与原生测试结果为准。

## 9. 开发验收计划

S1 使用独立源/目标测试目录，覆盖同盘与跨盘、中文空格路径、权限/空间失败、非空目标、路径别名与 junction、目录互相包含、WAL 未落盘、错误密钥、缺失 blob、复制中断及逐阶段崩溃恢复。验证失败不破坏源，成功保持记录/分组/设置和 blob 字节一致；目标丢失时有明确恢复入口，绝不静默建空库。隔离测试不得读写正式启动定位文件。

K1 通过隔离浏览器真实离屏键盘事件覆盖：三布局、首尾循环、无用户分组、空结果、搜索光标与选区、焦点进入列表/返回搜索、输入法、菜单/编辑/录制、在途请求乱序、连续切换后 Enter、敏感预览清理。离屏只证明前端行为；原生输入法与焦点仍由用户实机验收。

阶段代码完成后执行项目既有 fmt、全目标 clippy、Rust 测试、Prettier、ESLint、类型/Vite 构建，以及 handoff 所列受影响状态与离屏回归。Rust 环境和线程限制沿用 `scripts/env.ps1`。执行实现时按本节回归，不接管键鼠或桌面剪贴板，不改 manual 和真实偏好，不提交或推送。
