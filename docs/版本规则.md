# 版本规则与路线回溯

日期：2026-11-25。当前交付版本为 **0.8.2**，对应 K2 键盘导航、钩子恢复、内容忽略规则及 Fluent 提示样式收口。

## 编号规则

- 以 U2 完整验收为 `0.1.0`，此前实现包含在该基线中。
- 开发阶段使用 `0.功能批次.修订批次`：完成独立的大功能，递增第二段，第三段归零；验收后的修复、小功能补齐和品牌调整，递增第三段。
- 按已验收的交付批次计数，不把每次对话、提交、阶段内部步骤或 R 编号都换算成一个版本。阶段内部修复包含在该阶段完成版本中。
- 回归验收本身不增加功能批次；其中交付的产品修复计入修订批次。纯文档、测试材料和外测准备不单独升级应用版本。
- 测试包可在应用版本后增加预发布编号，例如 `0.6.2-alpha.1`。0.6.2 阶段的源码改号和首个公开预发布情况见下方历史记录。

## 配置与历史产物

应用版本同步维护在 `package.json`、`package-lock.json` 的根包信息、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 的应用条目和 `src-tauri/tauri.conf.json`。第三方依赖版本、数据库 schema 与归档格式版本独立管理。

README 的下载入口与“快速上手”同步展示当前公开可下载的 `v0.8.2`。

`v0.6.2` 已作为首个公开预发布版本发布，包含正式发布前的中文显示名纠正：当前简体中文界面显示“片筏剪贴板”，英文品牌为ClipRaft，未来英文界面采用英文名。当前没有语言切换功能，EXE仍为 `ClipRaft.exe`，数据标识不随显示名改变。发布源码和附件验收见 [0.6.2预发布验收结果](0.6.2预发布验收结果.json)。

版本回溯整理时，上述源码配置曾为 `14.0.1`，没有找到对应已验收路线或发布记录，随后按本规则统一为 `0.6.2`。Git 中原产品基线与已生成的旧程序仍为 `0.1.0`，两者需要区分。

版本回溯整理时，已冻结的 `0.1.0-alpha.1` 测试包、旧本地 EXE、校验值和验收报告保留原样。修改源码版本不会更改正在运行或已经生成的程序。随后用户授权重新构建 `0.6.2` 本地包、采用MIT许可，并推送到GitHub仓库；最新交付状态以 [项目交接](handoff.md) 顶部为准。旧外测包继续冻结，不替换用户正在使用的程序，不创建发布标签。
