## K2.1 主面板记录导航

### 问题与原因

- 用户反馈：在第一条按 ↑ 会跳到第 100 条并触发懒加载，用 Home 回到顶部后，再按方向键选中项又回到第 100 条附近。End 也有同样问题。
- `src/MainWindow.vue` 的 `navigateRecords` 按 `(selected ± 1 + items.length) % items.length` 只在已加载的记录（每页 `PAGE_SIZE = 100`）里循环，所以第一条按 ↑ 会落到已加载的最后一条。列表滚到底部后，`checkLoadMore` 又会加载下一页。
- 主面板没有处理 Home/End，看到的跳转是浏览器原生滚动了列表，`selected` 和焦点都没有变。

### 确定的行为

| 按键 | 行为 |
| --- | --- |
| `↑` / `↓` | 上一条/下一条。第一条按 ↑、最后一条按 ↓ 都停在原处，不再循环。已加载的最后一条按 ↓ 时，沿用现有逻辑先加载下一页 |
| `Home` | 选中第一条，滚到顶部，焦点移到该记录 |
| `End` | 加载完剩余分页后选中真正的最后一条，滚到底部，焦点移到该记录 |
| `PageUp` / `PageDown` | 按列表可见行数移动选中项，在首尾停住。到达已加载的末尾且还有更多记录时，先加载下一页再继续移动 |

- 普通、双列、紧凑三种布局共用这套规则。双列是两列网格（`.cards-layout:not(.compact) .list`），翻页步长按“可见行数 × 列数”计算。↑/↓ 在双列中仍按序号前后移动一条，保持现状。
- 快速面板的循环选择不变。它打开时冻结了全部历史顺序，没有分页问题。
- 焦点在搜索框、设置、分组编辑、菜单、原生下拉框或删除确认条时，这四个键保持原有行为：搜索框里 Home/End 移动文字光标，菜单保留自己的键盘协议。与现有 `navigationTarget` 的判断保持一致。
- 带 Shift、Ctrl、Alt 的组合不在本次范围，继续交给现有多选和快捷键逻辑。Shift+Home/End 之类的范围选择如有需要，另行确认。
- 移动后清除多选，关闭右键菜单，`resetOnShow` 的处理与现有 ↑/↓ 一致。

### End 与分页加载

- End 循环调用现有 `loadMore`，直到 `hasMore` 为 `false`。每页都检查 `listGeneration`，筛选或搜索变化后立即放弃这次跳转，不抢用户的新焦点。
- 加载期间显示现有的分页加载状态。期间用户按了其他导航键、点击记录或切换筛选，就停止继续加载，并以用户的新操作为准。
- 分页失败时停在已加载的最后一条，显示现有的 `pageError` 与重试入口。
- 默认保留上限是 1000 条，最多约十页。超大历史下 End 需要多次请求，这一点作为已知限制记录。以后如需优化，可以让后端直接返回末尾一页，不在本次范围。
- 键盘调度新增的按键用查表分发，不写 if-else 链。`src/mainKeyboard.ts` 现有的 `PanelNavigation` 可以扩展为 `first-record`、`last-record`、`previous-page`、`next-page`。

### 文档与回归

- 更新 [K1 主面板键盘操作实施与验收](K1主面板键盘操作实施与验收.md) 第 1 节的按键表：↑/↓ 改为“首尾停止”，新增四个键。保留历史记录，注明 2026-11-24 由 K2.1 修改。
- 在 `scripts/check-u2-ui.mjs` 的 K1 段附近新增专项，三种布局都要覆盖：
  - 首条按 ↑、末条按 ↓ 不移动，也不触发加载。
  - 超过一页时 Home、End 后选中项和焦点都在对应记录上，紧接着按 ↑/↓ 从新位置继续。
  - End 期间切换筛选，旧的加载结果不改变新列表，也不抢焦点。
  - End 遇到分页失败时停在已加载的末尾。
  - PageUp/PageDown 的步长和首尾停止，以及双列的列数换算。
  - 搜索框内 Home/End 仍移动文字光标。
- 现有回归 `scripts/check-m1-t4-ui.mjs` 跨页搜索的 ↑/↓ 断言保持通过。若有断言依赖主面板首尾循环，按新行为更新并在报告中写明原因。
## K2.2 键盘钩子健康监测与掉钩恢复

### 背景

- 低级键盘钩子回调超过系统 `LowLevelHooksTimeout` 时，Windows 可能静默移除钩子，且不通知安装方。表现为快速面板快捷键突然无效，只能重启程序。实现前按 Microsoft Learn 的 `LowLevelKeyboardProc` 文档复核这一行为。
- 现状：`src-tauri/src/hook/lifecycle.rs` 的 `Registration::install` 在 `keyboard-hook` 线程安装 `WH_KEYBOARD_LL` 和 `WH_MOUSE_LL`，之后只在退出时释放，没有检测与重装。

### 建议做法

- 回调路径只增加一次原子写：记录最近一次收到真实（非注入）键盘或鼠标事件的时间。不在回调里做判断、日志或系统调用。鼠标钩子记录鼠标移动，因此单独移动鼠标不会误判键盘钩子失效。
- 钩子线程使用 `SetTimer` 每 5 秒读取 `GetLastInputInfo`。系统最近输入比最近钩子事件晚超过 15 秒，且连续两次检查均超过阈值时，判定为疑似掉钩。阈值、周期、确认次数和失败退避均为命名常量。
- 重装在钩子线程内执行：先释放旧注册，再按现有 `Registration::install` 重新安装键盘与鼠标钩子，重装后用 `seed_state` 重新采样修饰键。重装期间若快速面板会话活动，按现有取消路径关闭，不提交选择。
- 重装成功或失败都写不含按键内容的诊断日志，并通过现有错误提示通道告知用户一次。失败后 60 秒内不重试，不进入忙循环。
- 不改变已验收的修饰键释放、0xE8 掩码、粘贴代号和焦点恢复规则。

### 验证

- 纯逻辑测试覆盖判定函数：正常输入、只有鼠标输入、短暂空闲、超阈值一次、连续两次超阈值、重装失败后的退避。
- 隔离环境中可以主动卸载钩子来模拟掉钩，验证检查能发现并重装。不接管真实键鼠；需要原生确认时由用户操作。
- B-09（主面板偶发首次唤出未到最前）若在本阶段再次出现，按[待修问题](待修问题.md)已登记的取证方式处理，不主动扩大修改范围。

本次自动测试覆盖健康状态机与旧注册释放/新注册安装的替换顺序；未在当前桌面安装系统级钩子模拟静默卸载，需在用户验收阶段确认实际掉钩后的恢复。

## K2.4 按正则或关键词忽略内容

- 设置「隐私」中新增“忽略内容规则”列表。每条规则选择“包含关键词”或“正则表达式”，命中则整条复制内容不记录。规则数量和单条长度设上限并提取为常量，例如最多 50 条、每条 200 字符。
- 判定只作用于记录的文本内容（`CF_UNICODETEXT`），图片和文件不参与。位置建议放在采集链路中现有忽略程序判断之后、写入存储之前（`src-tauri/src/clipboard/capture.rs` 与 `runtime/worker.rs` 一带），与 `ignored_apps` 的读取方式保持一致。最终位置以实际代码分层为准，不在键盘钩子或剪贴板消息线程里做匹配。
- 正则使用 `regex` crate。它已作为间接依赖出现在 `src-tauri/Cargo.lock`（1.13.1），改为直接依赖时复用锁文件版本。该库按线性时间匹配，主要风险是规则编译体积，用 `RegexBuilder::size_limit` 限制。规则在保存设置时编译校验，非法规则在对应行提示错误，不保存。
- 关键词匹配默认忽略大小写。被忽略时写一条不含内容的诊断日志（`reason=ignored_content`），与 `ignored_app` 一致。
- 规则只影响之后的复制，不回溯删除已有记录。
- 回归：设置校验（数量、长度、非法正则）、关键词与正则命中和未命中、大小写、超长文本的匹配耗时、规则修改后的即时生效、密码备份保留。
