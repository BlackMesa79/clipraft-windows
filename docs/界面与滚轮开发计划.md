### 自动更新（分两步）

- 现状：发布形式为 ZIP 解压运行，`src-tauri/tauri.conf.json` 中 `bundle.active` 为 `false`，未引入 updater 插件。Tauri 官方 updater 在 Windows 上按安装包更新，实现前按官方文档复核。
- 第一步（`0.8.1`）：设置新增「关于」分类，显示当前版本、检查结果、可用版本和发布说明，提供「检查更新」和自动检查开关。发现新版本时跳转 GitHub Releases 下载，不自动安装。稳定版默认只提示正式发布。
- 第二步（A1）：改用安装包并接入官方 updater，通过 GitHub Releases 发布签名更新产物和更新清单。用户可选择后台下载，安装及重启需明确确认。需要确认签名私钥保管、ZIP 老用户迁移、开始菜单与卸载行为。用独立测试包验证当前版、可更新、断网、下载中断、签名不匹配、重复点击及安装后重启，升级保留现有数据目录、历史记录和偏好。
- 不自写 ZIP 替换器。

### K2 可靠性与键盘补齐

- 主面板上下键在首尾停止；Home/End 选择第一条或真正最后一条，End 加载剩余分页；PageUp/PageDown 按可见行数移动，双列按两列计算。适用于普通、双列及紧凑布局。
- 钩子健康监测：低级钩子回调超时后 Windows 会静默移除钩子。周期性比较系统最近输入时间与钩子最近事件时间，判定掉钩后在钩子线程重新安装，写诊断日志，托盘提示恢复结果。不在钩子回调里增加耗时操作。
- B-09 若再次出现，按[待修问题](待修问题.md)已登记的取证方式在本阶段处理。
- 正则或关键词忽略内容：在 `capture_policy` 中执行，命中则整条不记录。限制规则数量与长度，避免正则开销拖慢采集。

### 设计边界补充

- U9：后端只判断是否为动画、按大小登记原始 GIF 或动画 WebP 字节，前端用 `<img>` 播放，暂停时切回首帧缩略图，离开记录或隐藏窗口时卸载。开工前先只读摸底来源格式：文件型记录只存路径，源文件删除后只剩首帧快照，是否采集时保存副本需单独确认；浏览器复制通常只给静态图和远程 `img`，现有策略不抓远程图片；注册格式 `GIF` 当前未采集，确认常用应用确实提供后再决定是否加入。
- E1：沿用[新增实用功能评估](新增实用功能评估.md)第 3 节的方案，只编辑纯文本，含 HTML/RTF 的记录保存后统一为纯文本并提示格式变化。不依赖 U9/U10。
- U10a/U10b：HTML 样式支持不代表 RTF 支持。U10b 先统计只含 RTF、没有 HTML 的记录占比，占比低时只显示纯文本和格式标识。
- 《孤星》取材于《明日方舟》SideStory。自用不受影响；随公开仓库或 Release 分发前，先确认名称与图片素材是否允许再分发，或改为不含原作名称和素材的原创主题。

### 候选功能池

以下功能已登记，未排入版本，开工前由用户选择：按来源程序自动归组、粘贴时文本转换、数字键直达（Ctrl+1～9）、多选依次或合并粘贴（宜在 E1 之后）、图片 OCR（`Windows.Media.Ocr`）、记录备注、拖出记录到其他程序（需原生 OLE 拖放）、以管理员身份重启、存储占用概览、英文界面、应用锁与主密码。二维码识别、脚本引擎和表情面板暂不考虑。

## 目标与约束

- 主窗口、设置、分组、菜单、预览采用一致的字体、间距、颜色与状态反馈。先延续现有浅色青灰配色，用代码原型核对布局；按用户最新方向，主题切换纳入本阶段，并与单列/双列布局独立；紧凑模式统一为无预览竖直列表。
- 快速面板透明、无边框、无窗口阴影，只显示卡片。默认 5 条，选中项居中；上下项通过透视、缩放、透明度与 rotateX 形成圆柱效果，过渡约 120～160ms。
- 卡片文字单行截断，文件显示文件名，图片保留缩略图；去掉格式名等技术信息，错误提示改为小胶囊。
- 选择范围覆盖全部历史并首尾循环，不能只把现有 9 条快照换个样式。打开时固定 id 顺序，之后新记录不插队，视图只保留选中项邻域。
- 保持默认选中第二条、只有一条选第一条、松开修饰键提交、Esc 取消。不改已验收的修饰键释放、掩码键、粘贴代号和焦点恢复规则。
- `publish()` / `panel_state` 不取 storage 锁；后端打码继续覆盖所有面板数据，敏感项不请求缩略图，删除/到期不能提交失效项。

## U3 进入实现前需要定稿的设计

1. 全历史 id 索引在后台维护并原子替换，Open 获取内存快照；不能在低级钩子、发布路径或首次显示中同步全表查询。记录数只影响 id 集合，不把全库正文和图片一次送给前端。
2. 邻域取数带会话编号和请求版本；关闭重开、连续翻动、删除与敏感状态变化后，旧响应不得覆盖当前状态。未加载项不得误用上一项内容提交；提交以选中 id 为准并校验仍有效。
3. 顺序冻结与内容安全更新分离：新增/重新复制不改变本次顺序，删除/到期移除或取消，敏感切换及时替换已缓存视图；不能仅刷新第一页而漏掉深处记录。
4. 先定义空、单条、少于可见条数、首尾循环、当前项被删除的纯状态行为，再接数据库与 UI。以原 M1 测试守住不重排、选中项失效取消和后端打码约束。

## 需求边界与验收风险

- 原“鼠标滚轮选择未实现”约束已由本轮补充取代：快速选择会话活动且原修饰键仍按住时，真实垂直滚轮复用Next/Previous动作；关闭后、横向和注入事件透传。quick仍穿透鼠标且不抢焦点，已获用户功能验收。
- `←/→` 分组切换是原文可选项，先完成全部历史；`Shift+V` 在默认 Ctrl+Shift+V 中与已有下一条含义重叠，不能直接改掉已验收的 V 行为。扩展键位在核心滚轮稳定后另行确认。
- 可见条数已有 3～15 持久化范围，U4 须明确偶数旧值的兼容展示规则，再决定 UI 是否仅给奇数选项；不为了视觉直接拒绝现存设置。
- 原文约 16ms 呼出是目标，需记录测量条件，不把离屏 DOM 测试当原生延迟证明。首次索引未就绪、锁等待与慢磁盘分别设计反馈，不以无限同步等待解决。
- WebView2 原生透明、125%/150% DPI、多屏黑底/残影与输入法只能由可验证原生路径或用户人工确认；不接管桌面进行自动验收。静态、后台、离屏优先，必要真实键鼠操作须事先明确授权。
- M1 遗留的慢网络状态检查、真实登录自启、钩子健康监测等继续记录，不混入界面改造。schema 暂无升级需求；新增依赖前先评估现有 Vue/CSS/Rust 是否足够。
