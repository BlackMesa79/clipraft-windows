## 目标与约束

- 主窗口、设置、分组、菜单、预览采用一致的字体、间距、颜色与状态反馈。先延续现有浅色青灰配色，用代码原型核对布局；按用户最新方向，主题切换纳入本阶段，并与单列/双列布局独立；紧凑模式统一为无预览竖直列表。
- 快速面板透明、无边框、无窗口阴影，只显示卡片。默认 5 条，选中项居中；上下项通过透视、缩放、透明度与 rotateX 形成圆柱效果，过渡约 120～160ms。
- 卡片文字单行截断，文件显示文件名，图片保留缩略图；去掉格式名等技术信息，错误提示改为小胶囊。
- 选择范围覆盖全部历史并首尾循环，不能只把现有 9 条快照换个样式。打开时固定 id 顺序，之后新记录不插队，视图只保留选中项邻域。
- 保持默认选中第二条、只有一条选第一条、松开修饰键提交、Esc 取消。不改已验收的修饰键释放、掩码键、粘贴代号和焦点恢复规则。
- `publish()` / `panel_state` 不取 storage 锁；后端打码继续覆盖所有面板数据，敏感项不请求缩略图，删除/到期不能提交失效项。

## U3 进入实现前需要定稿的设计

1. 全历史 id 索引在后台维护并原子替换，Open 获取内存快照；不能在低级钩子、发布路径或首次显示中同步全表查询。记录数只影响 id 集合，不把全库正文和图片一次送给前端。
2. 邻域取数带会话编号和请求版本；关闭重开、连续翻动、删除与敏感状态变化后，旧响应不得覆盖当前状态。未加载项不得误用上一项内容提交；提交以选中 id 为准并校验仍有效。
3. 顺序冻结与内容安全更新分离：新增/重新复制不改变本次顺序，删除/到期移除或取消，敏感切换及时替换已缓存视图；不能仅刷新第一页而漏掉深处记录。
4. 先定义空、单条、少于可见条数、首尾循环、当前项被删除的纯状态行为，再接数据库与 UI。以原 M1 测试守住不重排、选中项失效取消和后端打码约束。

## 需求边界与验收风险

- 原“鼠标滚轮选择未实现”约束已由本轮补充取代：快速选择会话活动且原修饰键仍按住时，真实垂直滚轮复用Next/Previous动作；关闭后、横向和注入事件透传。quick仍穿透鼠标且不抢焦点，已获用户功能验收。
- `←/→` 分组切换是原文可选项，先完成全部历史；`Shift+V` 在默认 Ctrl+Shift+V 中与已有下一条含义重叠，不能直接改掉已验收的 V 行为。扩展键位在核心滚轮稳定后另行确认。
- 可见条数已有 3～15 持久化范围，U4 须明确偶数旧值的兼容展示规则，再决定 UI 是否仅给奇数选项；不为了视觉直接拒绝现存设置。
- 原文约 16ms 呼出是目标，需记录测量条件，不把离屏 DOM 测试当原生延迟证明。首次索引未就绪、锁等待与慢磁盘分别设计反馈，不以无限同步等待解决。
- WebView2 原生透明、125%/150% DPI、多屏黑底/残影与输入法只能由可验证原生路径或用户人工确认；不接管桌面进行自动验收。静态、后台、离屏优先，必要真实键鼠操作须事先明确授权。
- M1 遗留的慢网络状态检查、真实登录自启、钩子健康监测等继续记录，不混入界面改造。schema 暂无升级需求；新增依赖前先评估现有 Vue/CSS/Rust 是否足够。
