## 本轮范围

## 实现

| 文件 | 职责 |
| --- | --- |
| `panel_neighborhood.rs` | Coordinator 复用纯 Session，维护加载/就绪/失败状态、校验响应、取消或重新取数 |
| `panel_neighborhood/read.rs` | 后台调用 `panel_items` 或分批 `existing_panel_ids`，保留响应版本及错误 |
| `panel_neighborhood/loader.rs` | 复用 Tauri blocking 任务，合并请求、有界响应邮箱、合并通知、清除和关闭 |
| `panel_session.rs` | 增加只读 ID 顺序快照引用，供完整有效性核对使用；原选择规则不变 |

- 每次移动或重试先清空旧视图，再发起新版本请求；旧成功和旧错误均不能覆盖当前状态。邻域最多 15 条，不向该缓存放入全库正文或图片。
- 收到历史变化时立即清空旧视图，作废在途邻域，异步核对整个冻结 ID 顺序。核对版本独立于选中位置，核对期间继续移动不会丢掉有效性结果；完成后按最新选中 ID 取数。
- 当前项缺失则取消；其他项缺失先完整核对，再重建邻域，不把局部视图当作全库有效性集合，也不以原下标替代缺失的选中项。查询失败保留选择并展示失败，可重试，不当作全库已删除。
- 提交直接消费后端选中 ID，不等待邻域；加载中或加载失败不会导致提交上一条显示内容。实际接入仍须使用存储加载校验，不能把协调器返回 ID 当作数据库存在性证明。
- 单个 Loader 最多一个在途读取、一个待处理请求和一个未消费响应。连续输入只保留最新待处理请求；旧在途结果在写入邮箱前再次校验。通知只表示邮箱可能有新结果，消费时允许为空。
- `clear` 清除旧工作，Loader 可供下一次会话使用；`close` 原子清除工作并拒绝新请求，不打断已在执行的 SQL，但拒绝其结果。取消会话时仍须取消 Coordinator，不能只清邮箱。
- 敏感变化在协调器收到历史变化后失效旧正文，重新读取时复用既有后端打码出口；本轮没有前端缩略图请求或运行时安全事件接入，不能宣称产品中的敏感竞态已全部验收。

## 下一步接入约定

第 4 步由 Controller 持有 Coordinator 和 Loader，reader 捕获共享 State，在后台取得 storage 锁并补文件状态；通知向控制线程投递邮箱就绪事件。避免将捕获 State 的 Loader 放回 State 形成引用环。

Open、方向输入、关闭、主窗口切换和失败取消必须统一协调会话及邮箱；Commit 使用协调器选中 ID。历史安全变化须接入全局版本门，覆盖“数据库已经修改但控制线程尚未处理 history-changed”时的旧结果发布竞态；不得仅靠前端显示版本。

前端仍待接入会话/位置/总数、局部选中位置、加载/失败状态，并保留现有列表外观。完成后补 Controller/前端集成竞态测试和原生清单，再进入 U4。
