录制完成或更改组合后，300ms防抖自动检测；也可点击“检测冲突”重试。已修改快捷键时保存前复检，后端在更换注册/写库前再次检查；已知冲突或检测失败不提交新快捷键，原设置和注册保持。未改快捷键时，既有占用提示不阻止保存其他设置。

| 检测结果 | 含义 |
|---|---|
| 当前由本应用注册 | 与broker当前实际注册的主热键等价，不误报自身占用，不注销它 |
| 未发现系统注册冲突 | 本次临时系统注册成功并已立即释放；不代表所有软件都没有相同操作 |
| 此组合已被系统或其他程序注册 | 系统返回已登记占用，提示更换组合 |
| 系统拒绝注册 / 检测未完成 | 其他系统错误、临时注册释放失败或超时，保持原设置，可重试 |

应用内部继续拒绝两个组合相同或修饰键组完全相同；不再提示启用合并。已知基础编辑组合、Win+L等仍拒绝，另补F12系统调试器保留键的拒绝，前后端一致。

## 能力范围

[Microsoft RegisterHotKey说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)提供注册成功/失败及系统错误，F12明确保留给调试器；不提供占用程序查询。这里基于可注册性判断系统登记占用，不能声称枚举了所有软件快捷键。

其他软件在自身窗口处理的快捷键、低级键盘钩子、部分系统快捷键及后续其他程序注册，无法完整预知；也不能可靠显示占用者名称。因此界面明确写“未发现系统注册冲突”，附检测范围。检测只代表当前时刻；主热键最终注册仍有原有失败回滚保护，快速面板仍依原钩子运行，未为长期占位而改变其协议。

## 实现与保护

- 新模块`src-tauri/src/hotkey_check.rs`，可注入注册接口测试错误分类和清理。现有broker线程用独立ID=2临时注册并立即释放；主热键ID=1始终保留。系统错误1409归为占用，其他错误单独提示。
- broker串行处理检查和更换请求；相同虚拟键/修饰键的旧预设与自定义表示视为等价。WM_HOTKEY忽略检测ID，检测期间即使消息入队也不唤出面板或粘贴。
- 临时释放失败后先重试清理，再允许下一次注册，避免同ID累积；退出时再次清理。注册失败不注销其他程序或当前主热键。[Microsoft UnregisterHotKey说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-unregisterhotkey)要求在所属线程释放，本实现一直在broker进行。
- 新`check_hotkeys`命令仅主窗口可调用；后台等待最多2秒，前端按序号丢弃旧检测结果，退出设置取消前端计时。后端检查不在钩子回调中执行，不抢焦点、不注入按键、不改真实偏好。
- 保存发生冲突时，在自动启动/数据库/热键更换之前返回，释放配置门。原来的注册失败回滚、数据库失败回滚和面板激活禁止改键保护仍在；运行时事务测试增加了检测冲突拒绝分支。
