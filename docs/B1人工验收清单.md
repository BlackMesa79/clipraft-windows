## 准备与启动

使用独立程序和独立配置，避免开发服务器在重启时断开。先退出日常使用的片筏实例，避免快捷键及监听冲突；不要在验收程序中设置系统自启动。验收程序默认隐藏，通过托盘打开即可。

在项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-b1-acceptance.ps1
```

当前细节复验程序：`.tools/focus-audit-bin/ClipRaft.exe`（此前版本保留；B1功能已验收）。数据和配置：`.test-data/b1-acceptance/`；不使用 `.test-data/manual`。重复运行同一脚本会保留此前验收数据和迁移后的定位，不能直接删除profile来“重置”。如需全新一轮，可给脚本加 `-Session b1-acceptance-second`，并用同一参数运行样本准备脚本。

已准备三类合成暂存样本：`.test-data/b1-acceptance/staging/`，对应路径记录在 `sample-index.json`。需要补充新样本时执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare-b1-staging-samples.ps1
```

## 第1组：密码弹窗、导出及取消

1. 自行复制两三条合成文本和一张不含私人信息的图片，创建一个分组，并将一条记录设为收藏。
2. 设置→数据存储，选择 `exports` 父文件夹，使用不存在的文件名，点击开始导出。设置页本身没有密码框；密码弹窗自动聚焦，Tab在框内循环，Esc仅关闭弹窗，重新打开为空白。
3. 两次密码不一致应拒绝开始；一致后正常导出，完成前不要退出程序。记住本次测试密码，不把它写到反馈日志中。
4. 可另做一次导出，在尚未发布时取消；最终目标文件不得作为完整归档留下。运行中可关闭/重开设置查看任务，迁移按钮不可用；发布阶段取消按钮禁用。

通过标准：文本、图片、分组/收藏仍在，已有文件不会被覆盖，密码仅在弹窗输入。

## 第2组：解密恢复、确认替换与真实重启

1. 导出完成后再复制一条“仅当前库新增”的合成文本，以便区分两份历史。
2. 恢复归档选择刚导出的包，目标设为 `restores/导入库1`（目录不能已存在）。输入错误密码应报错，当前历史不变；改用正确密码和同一个未创建的目标重试。
3. 验证成功后出现替换确认。先点“暂不替换”，确认仍能看到“仅当前库新增”；再从恢复结果区点击替换，勾选确认并重启。
4. 重启后应看到导出时的历史、图片、分组和收藏，不应包含导出后新增的那条记录。设置里的当前位置应为恢复目录；旧库仍保留在原位置，不与新库合并。

通过标准：实际进程重启后正确打开新库；错误密码、拒绝替换都不更改当前历史。若窗口未重新打开，先检查托盘，不重复触发迁移或删除任何目录。

## 第3组：迁移前备份、首次启动后源清理

1. 记录当前数据目录。使用设置→更改目录，选择 `migrated` 空文件夹。确认区应展示迁移前备份位置（目标同级 `.clipraft-backup-…`），并说明验证后才清理源文件。
2. 点击迁移并重启。进度先创建并验证备份，再复制并验证目标；重新启动后等待数据存储页显示“源清单文件已清理”。
3. 当前历史、图片、分组和收藏应完整；当前目录为 `migrated`。界面列出的备份目录应保留 `history.db`、`key.bin` 和对象内容。
4. 原源目录里的本次管理文件应被清理，源根目录、日志/缓存、锁及未知文件保留；不要要求整个源目录消失。
5. 正常情况下不会出现待清理错误。若出现“迁移成功，旧文件待清理”，确认当前仍是新库，再使用“重试源文件清理”；保存提示原文供反馈，不恢复旧定位、不删除备份。

通过标准：备份在源目录之外且保留；旧文件只在新库初始化后清理；失败不回滚新库。源被占用/内容变化/身份替换/备份损坏/部分删除后重试已由隔离自动测试覆盖，不要求用户手工损坏数据来复现。

本机迁移备份采用原数据库加密及原账户DPAPI密钥，不是跨电脑密码包。它含旧历史及可能的敏感内容，不随新库同步，需妥善保管。

## 第4组：中断暂存管理

1. 在“中断暂存管理”选择 `.test-data/b1-acceptance/staging` 并扫描。按 `sample-index.json` 区分样本。
2. `empty`：预检应显示0个文件；确认后移除该空暂存目录。
3. `partial`：预检应显示1个合成归档片段和文件大小。先取消，文件仍在；再次预检并确认，目录才被清理。
4. `unknown`：虽然标记可识别，但存在 `user-note.txt`，预检必须拒绝并保留它，不能按目录名直接删除。
5. 正式归档和迁移备份不应出现在可清理列表。扫描达到上限时会提示结果不完整。

通过标准：预检不删除文件，确认只处理清单；未知内容保留。活动锁、跨进程占用、文件预检后变更/替换、失效票据已由隔离自动测试覆盖。
