# 新增实用功能评估

日期：2026-11-15。范围：导入导出已确认排在 U5 之后；编辑新建和链接打开仍为评估。三项均未实现，未改现有加密方案。

## 1. 当前已确认的顺序

S1 数据目录与本机迁移 → K1 主面板键盘筛选 → U4 透明滚轮。K1 的左右切类型、Ctrl+上下切分组与搜索焦点规则覆盖普通、双列和紧凑模式。当前先实现 S1。

用户已确认：U5 完成 3D 滚轮整体回归与验收后，先进入 B1 密码保护的完整快照导入导出，再提供包含该功能的外部测试版，之后继续 U6～U8。外部测试反馈期间可修复缺陷，不将合并导入或文本编辑自动加入 B1。编辑仍独立排期。

## 2. 密码保护与跨电脑导入导出

推荐首版采用“导出时设置密码，导入时输入密码”。本机改目录继续使用现有密钥，无需密码；日常打开软件继续由 Windows DPAPI 解锁，不强制每位用户首次启动设置密码。

完整快照导出流程建议：冻结一致的数据快照 → 生成带版本和清单的加密归档 → 由口令派生封装密钥，保护归档及解密历史所需的主密钥。本地 `key.bin` 是 DPAPI 封装结果，不能只复制它并要求另一台电脑用导出密码打开。

在目标电脑输入密码后，先验证归档完整性、版本、内容清单、路径和空间，再在暂存目录恢复。独立新库导入可将解锁的历史主密钥重新用目标账户的 DPAPI 封装；不能直接拿导入的 `key.bin` 覆盖目标本机密钥。

向已有库合并时，需要先用源密钥解密，再按目标库密钥重新加密，并处理记录去重、分组 ID、设置与敏感到期。它与“恢复完整快照”属于不同操作。建议首版先做完整快照导出/恢复到新目录，后续再做合并导入。

口令派生优先评估 Argon2id 等适合口令的派生算法，参数须在独立实现时查阅官方标准、按目标设备测量并版本化；不能直接拿密码做普通 SHA-256 再当密钥。复用现有认证加密能力前应评审归档分块、随机数、密钥用途隔离与认证清单，不自造密码学算法。

需要覆盖：错误密码、篡改/截断、恶意派生参数、归档路径穿越、解压体积上限、取消/中断、目标非空与错密钥。密码不落日志或配置；忘记密码时不能承诺恢复导出包。本机仍能正常解锁时，可以重新导出并设置新密码。

首次启动设密码可作为以后可选的“应用解锁/跨电脑便携”能力，但它会扩大为解锁界面、自动锁定、改密和恢复策略。本次目录迁移不用依赖它。

## 3. 文本及链接编辑、手动新建文本

复杂度中高，建议作为单独的 E1 阶段。现有 `Clip::hash()` 根据完整格式内容生成 ID，存储还维护去重、搜索/拼音索引、链接识别、加密 blob 引用和敏感状态；编辑不是只更新列表中的 summary。

建议首版提供“编辑文本”和“新建文本”两个入口，使用同一个纯文本编辑器。图片、文件以及混合文件载荷不进入此编辑流程。手动输入单个网址仍按文本保存，随后由现有规则自动进入链接筛选。

保存规则建议：

- 通过专用接口获取可编辑的完整文本；不能把详情接口截断后的 20,000 字内容当作完整文本保存。超过编辑上限时明确拒绝，保留原记录；上限在阶段准备中定稿。
- 原记录含 HTML/RTF 时，编辑保存为一致的纯文本载荷，移除过时的富文本格式，并在编辑器说明格式变化，避免粘贴出修改前的富文本。
- 视觉上替换原记录；后台按新的内容 ID 在事务内写入并移除旧记录，保留创建时间、置顶、收藏、分组等元数据，更新去重键、搜索/拼音索引、链接标志和大小，提交后才回收失去引用的 blob。
- 编辑后与其他已有内容冲突，首版建议提示“内容已存在”并保留草稿，提供定位现有记录；不悄悄覆盖或合并两条记录的收藏、分组等属性。
- 原本敏感的记录不因编辑自动解除敏感；原来“确认不敏感”的结论不能无条件套给全新的文本，需重新执行检测。既有敏感到期时间不因普通编辑悄悄延长；受保护项继续沿用现有到期清除规则。
- 敏感文本先显式解锁再编辑；草稿不写浏览器本地存储、诊断或预览缓存。保存时检测记录是否已被删除、到期或发生并发变化，失败保留草稿，不自动重建被删除记录。
- 保存与手动新建不操作系统剪贴板、不自动粘贴；只有用户明确执行复制或粘贴才触发原动作。
- 与历史安全版本门、冻结 ID 会话及邻域缓存一起更新，旧 ID 不得继续粘贴出原内容。三布局共用编辑组件，编辑时屏蔽列表快捷键但保留文本框原生方向键。

应覆盖：文本变链接及反向变化、富文本编辑、去重碰撞、空文本/多行/Unicode、全文上限、保存失败、并发删除/到期、敏感重新检测、共享 blob 回收、搜索更新和快速面板失效处理。记录内容 ID 与元数据策略必须先定稿再实施。

## 4. 链接右键用默认浏览器打开

复杂度低于编辑，可独立为 L1 小阶段。现有链接不是独立底层 kind，而是文本记录的 `is_link` 索引；现有识别函数已限制为完整单条 http/https 链接，并解析主机。应复用这套识别规则，不根据摘要猜网址。

建议：单条有效链接的右键菜单增加“在默认浏览器中打开”；后端只接收记录 ID，读取并验证完整原文，再交给系统默认浏览器关联。前端如需显示资格，增加后端安全布尔标志，不提前泄露敏感网址。

仅允许 http/https，拒绝 file、javascript、自定义协议、控制字符及多条混合文本；不拼接 shell 命令。可复用 `file_actions.rs` 的主窗口权限、STA Shell 调用与错误映射结构，浏览器分发由新的链接职责模块负责。

敏感链接先显式解锁并由用户点击打开，不能因为显示菜单就发送网址；具体“已解锁”授权要在后端校验。打开前重新检查删除/到期及完整 URL。找不到默认浏览器、系统拒绝或记录失效时明确提示。

此操作会把网址交给外部浏览器，随后可能产生网络请求。验证优先使用替身分发器证明传给 Shell 的是验证后的 URL；原生默认浏览器打开由用户自行测试，不在后台自动打开真实链接。

## 5. 已确认排期与 B1 交付范围

顺序：**S1（用户已确认严重缺陷修复后实测正常）→ K1 → U4 → U5 → B1 密码导入导出 → 首批外部测试 → U6 → U7 → U8**。外部测试启动不要求等待 U6～U8；其反馈可持续收集。U5 仍只代表滚轮阶段验收，不能替代 B1 的专项验证。

B1 分步实现、最终一并提供给测试者：

1. **B1.1 一致快照与密码导出**：完整历史、分组、收藏及可迁移设置，归档版本、内容清单与完整性认证；密码在导出时设置，不强制首次启动设密码。
2. **B1.2 跨电脑恢复**：输入导出密码，在独立暂存/新目录校验并恢复，密钥重新由目标电脑的 DPAPI 保护。当前库先保留，明确确认后切换，不静默覆盖或合并。
3. **B1.3 迁移前备份与成功后清理**：复用完整快照能力，按第6节实现备份、校验、切换、首次成功启动后清理源管理文件；清理失败可重试，不回滚新库。
4. **B1.4 专项验收和测试版**：错误密码、坏包/截断/篡改、空间不足、取消/中断、版本不兼容、非空目标与已有库保护；重启、分组/图片/敏感记录及跨 Windows 账户/电脑由可验证环境测试。没有跨电脑环境不能宣称通过；为外部测试者准备步骤、日志边界和问题反馈清单。

首版“导入”指恢复完整快照；**向当前历史合并记录、部分导出、自动定时备份**后续单独安排，不为首次外测承诺这些扩展。文件型记录引用的原始用户文件不打进完整历史包，需明确说明换机后源文件可能不可访问。

L1 链接打开和 E1 文本编辑/新建的实施顺序尚未确认，不自动插到 K1/U4/U5 或 B1 之前。

## 6. B1.3：迁移完成后清理源目录（已确认排期）

用户提出“迁移前备份，再剪切”，可以减少源目录残留造成的非空冲突。建议将其定义为可恢复的迁移事务，而不是直接对活跃数据执行操作系统剪切：

- 停止写入并完成 WAL 整理，制作完整、可验证的加密备份；备份包含配套数据库、密钥与对象，不放在将清理的源目录内部。
- 同卷在具备合适目录布局时可用原子重命名减少复制；跨卷仍需要复制并校验目标，之后才删除源文件，不能把跨卷剪切视作原子操作。
- 目标验证、启动定位提交、首次从新位置正常初始化均完成后，再按清单清理源目录内的本次持久数据。定位配置、WebView 缓存、锁、日志与无关用户文件保留，不递归删除整个根目录。
- 进程在新目录开始写入后，以新目录为权威；源清理失败应提示“迁移成功，旧文件待清理”，可重试，不能退回旧快照，也不能显示迁移整体失败诱导重复搬迁。
- 清理前核对文件身份/清单，源位置出现后续新文件或原内容变化时不删除；备份保留位置和敏感残留要在界面说明，备份不等于同步副本。

**用户已确认将此流程纳入 B1，与导入导出一起开发。** 当前 S1 仍保持已验收的复制并保留源副本，不提前自动删除。B1.3 复用 B1 快照能力并做专项验收，不阻塞 K1/U4/U5。

## 7. R1：富文本样式预览（独立增强项，已确认登记）

用户在 B-10 实机验收通过后明确要求将富文本样式预览作为后续独立增强项，**不阻塞或插入 U4 前置**。当前只有安全文字/图片顺序块，不还原原文字体字号颜色与表格排版；普通粘贴仍使用保存的原始格式。

建议按可控范围逐步扩展，具体实施时间另行安排，不自动插到已确认的 U4→U5→B1 外测路线之前：

- 先规划 HTML 常见样式：粗体、斜体、下划线、受限文字颜色与字号、段落、列表及简单表格，保持普通/双列/紧凑浮窗一致。
- 在结构化安全节点中保留白名单语义和样式；不直接执行原始 HTML/CSS，不加载外网资源、不执行脚本或事件，不承诺与来源应用像素一致。
- RTF 解析与展示作为单独子范围评估，不能把 HTML 样式支持说成 RTF 支持。
- 继续覆盖敏感显式解锁、旧响应清理、解码/节点/尺寸限制、深浅主题可读性和原始粘贴格式不变。
- 本地引用图片的持久化另属采集/资源管理能力，R1 不自动承诺解决文件删除或跨电脑图片可用性。

本轮只登记规划，不增加产品实现；B-10已验收的图文顺序修复独立提交。
