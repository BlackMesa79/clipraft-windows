# M1 / T4 搜索与筛选验证报告

日期：2026-11-11。状态：实现和自动化验证完成，桌面人工验收待执行。未提交代码；保留任务开始时已有的 pinyin 0.10 依赖及 Cargo.lock 改动，未添加其他依赖。

## 实现范围

- v4 迁移：items 新增 search_pinyin TEXT NOT NULL DEFAULT '' 与 is_link INTEGER NOT NULL DEFAULT 0；增加 items_link 索引、items_fts_map(search_id INTEGER PRIMARY KEY, item_id TEXT UNIQUE NOT NULL REFERENCES items(id)) 和 items_fts(search_text,search_pinyin) FTS5 trigram 表，以及新增、删除、搜索字段更新三种触发器。
- 采用独立 FTS 内容和显式整数映射，避开 items 隐式 rowid 在 VACUUM 后变化的问题。代价是多存一份可搜索内容；所有对象仍在 SQLCipher 加密库内。没有改变原 items 主键、formats 外键、dedup_key、owner_flush、修饰键、掩码键或粘贴代号。
- 保存准备阶段计算拼音/链接；迁移每批 128 行回填并建立索引，提交前 integrity-check。仍使用既有加密备份与逐版事务回滚。新库与 v0 迁移库完整 schema 一致；v3 回填、失败回滚、备份不覆盖和重复打开均通过。
- query 按空白拆词并取 AND；≥3 字符的词安全构造 FTS 字符串字面量，短词用已转义 LIKE。支持全拼、首字母、拼音片段、中文和英文组合。kind=text 包含 rich，新增 kind=link，与 favorite_only、group_id 共同生效，排序及 offset/limit 维持原行为。
- 主窗口搜索框约 150ms 防抖、五类分段筛选、空态和首条选择；删除按当前过滤条件重建。过期分页、详情响应及等待旧分页的方向键不能覆盖新搜索状态。
- runtime 仅增加 main-shown 通知；前端 nextTick 后调用输入框 focus，不调用 Tauri set_focus。list_items 直接使用扩展后的 ListFilter，无需改命令签名；快速面板继续使用默认全部缓存。

完整 schema 与升级约定见 [M1 存储层说明](M1存储层说明.md)。

## 键盘冲突规则

搜索框 ↑/↓ 移动列表，Enter 粘贴，Shift+Enter 纯文本粘贴。非空搜索框 Delete 只编辑文字，包括末尾不删除记录；空框 Delete 才删除所选记录。搜索框 Ctrl+A 选文字，列表 Ctrl+A 全选已加载记录。输入法组合输入状态、isComposing 或 keyCode=229 时不处理列表快捷键。

Esc 优先处理设置页、删除确认条、右键菜单，再清空非空搜索，搜索已空才隐藏；类型筛选保留。设置页开启时 main-shown 不夺走设置字段焦点；返回列表恢复搜索焦点。

## 5000 条搜索性能

## 风险与人工待验

1. 原文最多 16KiB，拼音仅前 2000 个汉字且使用默认多音字读音；不做繁简/声调归一。FTS 与短 LIKE 的非 ASCII 大小写规则可能不同。
2. 图片无 OCR，缺少 CF_UNICODETEXT 的富文本不能按纯文本内容搜索。链接仅验证格式，不联网判断可达性。
3. 独立 FTS 的内容副本和索引增加数据库体积；大库首次迁移会占用时间与额外磁盘。备份只包含数据库，不是完整 blob 备份，沿用现有风险说明。
4. 未来编辑内容/kind 的代码必须一起重新计算 search_pinyin/is_link，触发器只维护索引副本。
5. 真正打开主窗口、中文输入法候选、原生目标激活、Enter/Shift+Enter 跨应用粘贴需按 [人工清单](M1人工验收清单.md) 复测。本轮没有宣称桌面人工验收通过。
