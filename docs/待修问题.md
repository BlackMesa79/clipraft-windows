# 日常使用待修问题

记录日期：2026-11-12。M1 最终人工验收通过后，用户补充日常使用中观察到的两个问题。用户要求先记录，正式开发时同步修复；本轮未复现、未改产品代码，也未读取人工数据或操作桌面剪贴板。

两个问题均影响核心粘贴流程，列为下一阶段优先修复项。当前不能确认二者是否同源，也不能仅凭截图判定修饰键、输入法或钩子故障。

## B-01 主面板 Enter 粘贴时出现输入法候选窗

- **状态**：用户已报告，有截图；尚未复现、未定位。
- **触发描述**：某些情况下，呼出主面板、选中记录、按 Enter 后出现异常。
- **截图可见事实**：目标输入区域附近出现输入法候选窗，编辑区有小写 `v`，候选中可见大写 `V`。截图不足以证明完整键盘事件序列。用户原始截图位于此前聊天，当前工作区未保存原图；可见现象已在此文字归档，新对话不可假设能访问原附件。
- **期望**：Enter 按既有流程向原目标粘贴选中记录，不产生额外 `v/V` 输入或意外输入法候选。
- **待补环境**：目标软件及版本、输入法与中英文状态、主窗口快捷键、是否已有未提交的输入法组合文本、记录类型、实际是否成功粘贴或只出现字符、可复现频率。
- **未来定位入口（不是已确认原因）**：主窗口 Enter 处理及 composition 状态、窗口隐藏/焦点交接、修饰键逻辑状态、SendInput 请求和返回。优先结合对应会话诊断时间线，不直接增加修饰键补发或盲目延时。

## B-02 新聚焦输入框后首次快捷面板快捷键直接粘贴

- **状态**：用户已报告；尚未复现、未定位。
- **触发描述**：聚焦到某个软件的输入框后，第一次按对应快捷键没有显示快捷面板，而是直接发生粘贴；第二次按同一个快捷键就正常。
- **期望**：第一次也应先呼出面板，选择后按约定释放修饰键才提交；不能在用户尚未选择时直接粘贴。
- **未知项**：具体软件、实际快捷键组合、先按/后松的顺序、按住时长、输入法状态、当时粘贴的是当前系统剪贴板还是某条历史、是否每次切换焦点都出现或仅程序启动后出现。不得自行补全为默认 Ctrl+Shift+V 或认定目标软件截获。
- **未来定位入口（不是已确认原因）**：钩子 Open/Commit/Cancel 事件与修饰键快照、面板 ready/visible 状态、目标焦点变化、粘贴代号、目标软件自身快捷键处理。区分“未触发面板”“触发后立即提交”和“面板状态变化但未实际显示”。

## 正式开发时的处理顺序

1. 主对话整理合成复现步骤，在改造输入相关路径前保存证据。只有确有需要时读取 `.test-data/manual/diag.log` 的相关会话；不修改或清理用户测试数据。
2. 测试交 Tester（assistant_id=3，codeg-mcp 路由）；优先纯状态机、事件序列、隔离窗口站与离屏测试。Tester 不改产品实现，主对话负责修复。
3. 不以自动化直接发送真实桌面按键。原生目标软件/输入法复现由用户操作；如确需接管键鼠，事先说明窗口、操作与占用范围并取得明确同意。
4. 修复前后分别验证两个场景：B-01 的 Enter 粘贴与候选窗；B-02 的首次呼出、持续按住、取消、松键提交和第二次呼出。补测主窗口/快速面板连续切换、不同松键顺序及不切输入法等 M0 已修复场景。
5. 保留实际应用与输入法的人工验证结果。仅纯状态机通过不能将原生缺陷直接标为已修复；修复后更新本清单、测试报告和 handoff。

本清单记录新的已知问题，不撤销此前已完成的 M1 验收历史，也不意味着当前版本已无待修项。
