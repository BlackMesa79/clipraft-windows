界面已按后续要求改用“取消敏感删除倒计时”“无删除倒计时”等明确文案，不再将该功能称为“永久保留”。历史文档文件名保留，避免破坏既有链接。

## 功能与规则

- 敏感图片默认显示后端生成的粗粒度马赛克预览；使用登记过的预览对象，不将清晰图交给 CSS 遮挡。右侧不再显示重复的“敏感内容”标题与缺图错误占位，按钮、图片、说明和底部操作分开排版。
- “显示原文”通过原有主窗口专属入口返回清晰图片预览；“隐藏原文”恢复马赛克。切换记录、隐藏窗口、进入设置、历史刷新或卸载时释放图片临时地址；迟到结果按原详情代号拒绝。
- 普通缩略图协议继续拒绝敏感图片。列表/快速面板仍保持锁标记和安全摘要；紧凑浮动预览显示同一马赛克，不提供清晰图入口。不改变图片粘贴内容或文件操作权限。
- 右键选中的敏感记录，使用“取消敏感删除倒计时”；支持多选，已取消项显示“已取消敏感删除倒计时”并禁用重复操作。无倒计时的记录标记仅显示“敏感”。
- 设置项改为“敏感内容保留时长”，数字后增加“分钟”，范围改为 0～1440，说明“0 为不设敏感删除倒计时”。保存 0 会在同一数据库事务中取消现有所有敏感项倒计时，之后自动识别或手动标记的敏感项也不再设置到期时间。
- 按用户澄清，单条和全局“永久保留”仅取消敏感标记的删除倒计时；普通历史的天数/容量/条数清理仍然适用，置顶、分组等原有保护不变，仍允许手动删除。使用现有 `expires_at=NULL` 状态，无新增 schema、依赖或全局开关。
- 全局从 0 恢复正数时，已经取消敏感删除倒计时的记录不会被追溯启动倒计时；之后新标记的记录使用新时长。现有无敏感删除倒计时的记录若需要重新倒计时，可在正数时长下取消敏感标记后重新标记。
- 保存敏感状态时复核数据库中的全局 0 设置，防止后台先取得旧时长、后提交保存而重新写入倒计时。

## 实现位置

`storage/detail.rs` 和 `thumbnail.rs` 负责登记预览读取及马赛克生成；`ItemDetail.image` 是可选图片字节字段。主窗口仍按现有 `reveal_item` 权限校验显式查看，普通正文接口只返回处理后的图片。

`detailImage.ts` 统一创建/释放 Blob 地址，供详情控制器和只读浮窗复用；`PreviewImage.vue` 支持该临时图片源。CSP 仅为图片增加 `blob:` 来源，原脚本与连接规则不变。

`storage/sensitivity.rs` 和 `storage/settings.rs` 实现敏感倒计时取消及全局 0；`storage/maintenance.rs` 已移除本轮误加的豁免，恢复原普通历史清理逻辑；新 IPC 复用 `update_history` 的主窗口权限、历史安全版本门和刷新路径。设置候选/前端校验与服务端边界同步改为 0～1440。
