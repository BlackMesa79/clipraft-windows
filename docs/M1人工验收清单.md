# M1 人工验收清单

本轮范围：T1 存储迁移、分页列表、D-6 图片去重与文件去重；T2 删除、孤儿扫描、自动清理与 VACUUM（当前 schema v3）。日期：2026-11-10。

以下为待人工执行项目，自动化通过不等于这些项目已经验收。不要让代理修改 `.test-data\manual`；人工测试使用独立副本，例如 `.test-data\m1-manual-20261110`。

## 准备

- [ ] 退出正在使用待复制数据目录的程序，保留完整 M0 测试库副本（`key.bin`、`history.db`、`data/blobs/`）。不要只复制仍在写入中的 `history.db` 而遗漏 WAL。
- [ ] 从项目根目录执行 `. .\scripts\env.ps1`，设置 `$env:CLIPBOARD_M0_DATA_DIR` 为独立测试目录绝对路径，再运行 `npm run tauri dev`。任何新的 cargo / npm tauri 进程都重新加载环境脚本。

## 旧库升级

- [ ] 使用包含文本、大文本、图片、文件记录的 M0 副本启动新版本：历史数量和顺序正常，文本详情、原图、缩略图、大预览和文件路径均可读取。
- [ ] M0/v0 数据目录出现 `history.db.bak-v0`；T1/v1 数据目录出现 `history.db.bak-v1`。T1/v2 数据目录出现 `history.db.bak-v2`。升级后版本为 v3，原有重复文件记录的数量与格式保持不变。同名备份已存在的另一份测试副本应生成带时间戳的备份，旧备份不被覆盖。
- [ ] 退出重开：历史保持正常，不再生成升级备份。
- [ ] 单独保留已有备份及原始密钥/对象目录。不要在验收中把旧备份直接覆盖当前工作的数据库；恢复验证只在另一份隔离副本执行。
- [ ] 使用自动化结果核对新旧 schema、时间列、size、失败回滚与备份同密钥可读；生产应用没有开放人为失败开关。

## 分页和选择

- [ ] 准备至少 250 条不同内容的测试历史。主窗口首屏加载 100 条；滚动至底部继续加载，能够看到第 201 条及以后内容，最终提示已加载全部。
- [ ] 在第一页选中一条，滚动加载后续页面：选中记录不变，文本/文件详情不被清空或切换到别的记录。
- [ ] 选中第 200 条以后的记录，再从其他程序复制新的测试内容：历史刷新后仍选中原记录，详情正确；连续复制时无重复列表条目或明显错位。
- [ ] 鼠标滚动、方向键跨页、回车粘贴、Shift+Enter 纯文本、双击粘贴保持可用。最后一页没有永久“正在加载”，窗口缩窄后仍能滚动和查看详情。
- [ ] 快速面板呼出速度及原有选择/提交行为正常；本轮快速面板仍使用现有缓存范围，不要求翻遍全部历史。

## 文件记录去重复测（v2）

- [ ] 在独立测试库中，先从桌面复制一个图片文件，粘贴到 QQ 后在 QQ 输入框里再复制：应该只保留一条该文件记录，记录移到顶部，格式仍是第一次保存的那组（资源管理器的 CF_HDROP 与 Preferred DropEffect），不新增 QQ 的位图 blob。可先复制一条无关文本，再在 QQ 里复制以观察顺序变化。
- [ ] 反过来先从 QQ 复制，再从桌面复制同一文件：仍只保留一条，首次保存的 DIB/DIBV5/HTML 格式保留。
- [ ] 同一路径分别“复制”和“剪切”：保留两条不同记录；回贴时仍分别符合复制和移动语义。只用可丢弃的测试文件验证移动。
- [ ] 升级前已有多条重复记录时，它们全部保留；再次复制只更新其中最近使用的一条，不增加记录。旧重复项可使用主窗口的删除功能自行清理。
- [ ] 将同一图片作为纯位图复制（不含 CF_HDROP），可以与文件记录各保留一条，这是本轮已知限制。

## 退出固化复测（owner_flush）

- [ ] 开启诊断，在 XnView MP 中复制一张图片，等待文件记录保存后关闭 XnView：不会多出仅含位图的记录，原记录顺序和使用时间不变；日志出现 `capture sequence=N result=skipped reason=owner_flush`。优先复测 4835×7253 图片，并确认格式由 HDROP + DIBV5 + 文本缩减为位图。
- [ ] 用截图工具（如 Win+Shift+S）连续截取两张不同图片：两张都被记录，预览分别对应两次截图，不因 owner 为空而漏记。
- [ ] 复制图片并确认记录后手动删除该条，再关闭来源程序：内存上下文已失效，此次固化不应命中 owner_flush，可以重新采集位图。自动清理后也应保守失效。
- [ ] 来源仍有 owner 时重复复制，继续遵守已有去重和 touch 行为；原有自写回与占用重试无变化。

## T2 单条、多选删除和右键菜单

- [ ] 在独立测试目录准备至少 250 条不同记录，包含纯文本、大文本、图片和文件。单击只选中一条；Ctrl+单击加入或移出选择；Shift+单击从上次锚点选择连续范围。Ctrl+A 只选择当前已加载记录，首屏应为 100 条，滚动后可选择更多。
- [ ] 选中一条后按 Delete：不弹确认条，记录消失，选择落到该原位置的后继。删除最后一条时回退到前一条；删到空历史后显示空态，不再有可粘贴按钮。
- [ ] 在两页以上的列表中多选连续和不连续记录，按 Delete，界面显示“将删除 N 条 / 确认 / 取消”。确认后批量消失；分别验证“取消”和 Esc 不删除。没有确认条时按 Esc 仍隐藏主窗口。
- [ ] 对未选记录右键：选中该条并弹出 HTML 菜单。右键已选集合中的一条：保留多选；“删除”进入相应单条或批量流程，“粘贴”粘贴右键那一条。点击菜单外关闭；在窗口右下角右键，菜单不超出窗口。
- [ ] 删除第一页中间的条目，再滚到底部：后面的条目不遗漏、不重复。删除全部已加载记录但库中还有后续记录时，应显示并选中下一条，继续分页正确。批量删空全部记录后快速面板不能呼出旧记录；再复制一条新记录，主窗口和快速面板恢复可用。
- [ ] 删除操作期间重复按 Delete/Enter 不重复提交或粘贴；失败时显示错误并保留列表，列表刷新失败时“重试”可以重建。由于本轮没有生产故障注入开关，此项也可核对离屏合成 IPC 测试报告。
- [ ] 确认原有 Enter、Shift+Enter、双击粘贴、方向键、详情刷新和分页样式保持可用；快速面板不提供删除菜单或 Delete 删除功能。

- [ ] 对选定的独立测试数据目录，在删除图片前后统计 `(Get-ChildItem -LiteralPath '<测试目录>\data\blobs' -File).Count`。单条删除只回收其不再共享的对象；纯内联文本的删除可能不改变文件数，不能把这视为失败。
- [ ] 用同一合成测试图片，分别保存“文件记录”和“位图记录”。删除其中一条后另一条的共享缩略图/大预览仍能显示，且源图片文件仍在；再删除另一条后不再引用的 blob 才回收。具体共享哈希也已由 `file_and_bitmap_records_really_share_generated_previews` 自动测试验证。
- [ ] 退出应用后，在**独立测试目录**的 `data/blobs` 内放入：一个确认不存在且未引用的 64 位小写十六进制文件（例如 64 个 `f`，若已存在则换一个新名字）、一个 `t2-orphan.tmp`、一个 `t2-keep.txt`。不要覆盖已有文件，不要修改真正被引用的 blob。记录目录清单再启动：孤儿哈希与 tmp 消失，非哈希文件保留，已有图片仍可读取。
- [ ] 可另外放入 64 位大写十六进制文件和 `folder.tmp` 目录，确认扫描不碰它们。扫描只处理直接普通文件，不递归。
- [ ] 开启 `$env:CLIPBOARD_M0_DIAG='1'` 后，启动日志应有 `orphan_scan blobs=... temps=... failed=...`。文件被占用导致失败不会让已提交的记录删除失败，解除占用并重启后可回收；这条已有 Windows 无删除共享锁自动测试。
- [ ] 保留完整数据库、密钥和 blob 备份。**不要以为 `history.db.bak-v*` 单独足够恢复：旧库引用的 blob 可能已被后续删除或扫描回收。**

## T2 清理策略与 VACUUM

T2 只用默认策略，不读 settings，不提供临时环境变量覆盖。自动化用小策略覆盖边界；人工需较短流程时，只在项目内另建独立工作副本，临时修改 `src-tauri/src/storage/maintenance.rs` 的 `RetentionPolicy::default()` 为 `max_items: 3`、`max_bytes: 1024 * 1024 * 1024`、`max_days: 0`，使用独立测试数据目录编译运行。验证后恢复这三项为 1000 / 1 GiB / 30，不提交临时值，不对真实库试验。

- [ ] 小策略下复制 3 条不同内容，退出重启应恰好保留 3 条；复制第 4 条，等待满 30 秒后再复制第 5 条，清理应只留下 touched 最新的 3 条。注意定时本身不会触发清理，必须发生新的插入。
- [ ] 在一次清理后的 30 秒内快速新增至少 20 条不同记录，应在第 20 次新插入触发清理。重复复制同一条不计入新增数、不触发该节流条件，但会更新最近使用时间和排序。
- [ ] 默认保留天数依据 used_at，而非 created。max_days=0 不按天数删除；置顶、收藏或已分组记录不受普通策略清理且不计数/空间。这些字段尚无操作 UI，不要求人工编辑 SQLCipher 数据库，核对自动化边界测试即可。
- [ ] 空间按 size 逻辑字节累计；最新一条即使超过空间、过旧或到期也保留。其他 expires_at 到期记录突破置顶/收藏/分组保护。本轮没有敏感规则和定时到期驱动，T7 再接入。
- [ ] 在独立库选中恰好 200 条删除，日志不应因这一单次删除触发 VACUUM；再准备至少 202 条，单次删除 201 条，日志应有 `vacuum elapsed_ms=... ok=true`，剩余条目重启后依然可读取。批量删除允许清空最新条目，这是手工删除与自动清理的区别。
- [ ] 启动空闲页比例严格大于 25% 执行 VACUUM，已经通过启动清理整理时不重复。SQLCipher/WAL/secure_delete、启动空闲页整理及整理后重开可读由自动化验证；日志未出现 VACUUM 也可能是比例未达到条件，不视为失败。
- [ ] 观察实际数据量下整理耗时和随后采集是否恢复；大量删除或 VACUUM 会持有 storage 锁，可能延后采集/粘贴，快速连续复制可能合并。本轮不要求在用户其他高负载任务期间做压力测试。

可单独运行后端边界测试和离屏 UI 检查（不操作桌面键鼠）：
