# M1 人工验收清单

本轮范围：T1 存储迁移、分页列表、D-6 图片去重与 v2 文件去重。日期：2026-11-10。

以下为待人工执行项目，自动化通过不等于这些项目已经验收。不要让代理修改 `.test-data\manual`；人工测试使用独立副本，例如 `.test-data\m1-manual-20261110`。

## 准备

- [ ] 退出正在使用待复制数据目录的程序，保留完整 M0 测试库副本（`key.bin`、`history.db`、`data/blobs/`）。不要只复制仍在写入中的 `history.db` 而遗漏 WAL。
- [ ] 从项目根目录执行 `. .\scripts\env.ps1`，设置 `$env:CLIPBOARD_M0_DATA_DIR` 为独立测试目录绝对路径，再运行 `npm run tauri dev`。任何新的 cargo / npm tauri 进程都重新加载环境脚本。

## 旧库升级

- [ ] 使用包含文本、大文本、图片、文件记录的 M0 副本启动新版本：历史数量和顺序正常，文本详情、原图、缩略图、大预览和文件路径均可读取。
- [ ] M0/v0 数据目录出现 `history.db.bak-v0`；T1/v1 数据目录出现 `history.db.bak-v1`。升级后版本为 v2，原有重复文件记录的数量与格式保持不变。同名备份已存在的另一份测试副本应生成带时间戳的备份，旧备份不被覆盖。
- [ ] 退出重开：历史保持正常，不再生成升级备份。
- [ ] 单独保留已有备份及原始密钥/对象目录。不要在验收中把旧备份直接覆盖当前工作的数据库；恢复验证只在另一份隔离副本执行。
- [ ] 使用自动化结果核对新旧 schema、时间列、size、失败回滚与备份同密钥可读；生产应用没有开放人为失败开关。

## 分页和选择

- [ ] 准备至少 250 条不同内容的测试历史。主窗口首屏加载 100 条；滚动至底部继续加载，能够看到第 201 条及以后内容，最终提示已加载全部。
- [ ] 在第一页选中一条，滚动加载后续页面：选中记录不变，文本/文件详情不被清空或切换到别的记录。
- [ ] 选中第 200 条以后的记录，再从其他程序复制新的测试内容：历史刷新后仍选中原记录，详情正确；连续复制时无重复列表条目或明显错位。
- [ ] 鼠标滚动、方向键跨页、回车粘贴、Shift+Enter 纯文本、双击粘贴保持可用。最后一页没有永久“正在加载”，窗口缩窄后仍能滚动和查看详情。
- [ ] 快速面板呼出速度及原有选择/提交行为正常；本轮快速面板仍使用现有缓存范围，不要求翻遍全部历史。

## 文件记录去重复测（v2）

- [ ] 在独立测试库中，先从桌面复制一个图片文件，粘贴到 QQ 后在 QQ 输入框里再复制：应该只保留一条该文件记录，记录移到顶部，格式仍是第一次保存的那组（资源管理器的 CF_HDROP 与 Preferred DropEffect），不新增 QQ 的位图 blob。可先复制一条无关文本，再在 QQ 里复制以观察顺序变化。
- [ ] 反过来先从 QQ 复制，再从桌面复制同一文件：仍只保留一条，首次保存的 DIB/DIBV5/HTML 格式保留。
- [ ] 同一路径分别“复制”和“剪切”：保留两条不同记录；回贴时仍分别符合复制和移动语义。只用可丢弃的测试文件验证移动。
- [ ] 升级前已有多条重复记录时，它们全部保留；再次复制只更新其中最近使用的一条，不增加记录。旧重复项待 T2 删除功能完成后自行清理。
- [ ] 将同一图片作为纯位图复制（不含 CF_HDROP），可以与文件记录各保留一条，这是本轮已知限制。

## D-6 图片去重

- [ ] 分别从至少两个程序复制同一测试图片；在受支持格式集合与有效内容相同、差异仅为尾部填充时，只更新原记录顺序，不新增重复记录。
- [ ] 分别复测 PNG、24 位 DIB、32 位 DIBV5（含透明度），缩略图和大预览正常，粘贴回目标程序后像素与透明度未损坏。
- [ ] 如果不同程序仍产生两条记录，记录程序名和格式列表，区分编码/格式集合差异与尾部填充问题；本轮没有做跨编码的像素级去重。
- [ ] 旧的带填充记录可能与首次规范化后的新记录各保留一条；迁移不会重写旧哈希、旧 blob 或合并旧记录。

## M0 关键回归

- [ ] Ctrl+Shift+V / Alt+V 操作后输入法与布局不变，没有多余系统菜单；Alt+空格仍可用。
- [ ] 先松 Ctrl、先松 Shift、同时松开、Esc 取消后均无卡键或持续“请松开修饰键”。
- [ ] 最小化或遮挡后 Alt+V 能恢复主窗口；大图连续粘贴、新意图取消旧任务与成功后的排序保持正常。
- [ ] 自写回不重复采集、短时占用后重试、耗尽只报告一次等采集策略不退化。
