## 新增日志含义

| 标记 | 用途与关联 |
|---|---|
| hook_started | 钩子线程建立及broker接收线程；不能证明之后每个系统按键都到达 |
| frontend_ready | 主窗/quick就绪及当时hook_ready |
| quick_trigger | 面板关闭时也记录配置触发键候选：down、repeated、active_before、ready、gate_reserved、recording、held、expected、action；held/expected为修饰键组合掩码 |
| hook_dispatch | 动作投递结果与generation；accepted=false表示未成功投递；其t_ms是诊断线程处理时刻，非原始按键时刻 |
| panel_action / panel_open | 控制器收到动作、代号是否当前、session、打开/无目标/启动失败等结果 |
| panel_publish | 发给quick的session/serial、visible/loading/items数量/error布尔值，不记录摘要或记录ID |
| quick_window / quick_show | 原生显示排队、回调、返回时的可见性、宽高与前台句柄，以及显示返回成功/失败；不是桌面截图证明 |
| panel_frontend Received / Frame | 前端采用的session/serial与帧回调阶段；快速连续状态允许合并/取消旧帧；Frame不是实际桌面已绘制的保证 |
| paste_request | generation、restore、plain、target；区分主窗恢复目标与quick沿用目标 |
| focus_probe | before_prepare/after_prepare/before_send/after_send：同一generation的目标/子焦点句柄、类名、PID/TID/HKL、前台句柄及GUI查询是否成功 |

B-01以paste_request/focus_probe和原有SendInput记录对应；B-02从quick_trigger逐级查到hook_dispatch、panel_open、publish、原生show和前端状态。缺某一阶段是定位线索，不直接视为该阶段代码错误。没有quick_trigger时还须确认诊断已启用、时点正确以及钩子是否收到该输入，不能据缺日志否认用户现象。

## 隐私与执行边界

新触发诊断仅处理**配置触发键且有修饰键采样/缓存或面板已活动**的真实事件。普通无修饰输入、其他键和注入键不进入新候选日志。若修饰键既未被系统采样也未进入缓存，该候选仍可能不记录，这是有意保留普通输入隐私的边界。

钩子只向原诊断线程PostThreadMessage固定数值，不格式化字符串、不查询窗口、不等待文件；诊断队列失败计入既有dropped。其他路径仅只读窗口元数据；不读取窗口标题、正文、IME组合文本、剪贴板内容或普通字符，前端只传stage/session/serial。

诊断必然有少量采样/IPC开销，不承诺与未开诊断时绝对等时；没有加入人为延时或改变原行为判定。前端仅在frontend_ready返回诊断开启后异步上报，失败只记录console，不影响panel_state或粘贴。
