# 未来功能待办

登记日期：2026-11-16。用户已确认云备份和云同步作为未来功能；本轮不开发、不接入云服务、不上传数据。macOS仅为可能的未来适配方向，尚未承诺排期。

## C1：加密云备份

- 在当前一致快照、密码认证加密归档基础上增加上传/下载及备份版本管理。
- 默认只上传客户端加密后的归档，服务端不持有明文内容或解密密码。
- 设计手动/定时备份、保留周期、空间限制、失败重试和断点处理；明确整包备份的恢复语义，不把它称为双向同步。
- 验证错密码、损坏包、过旧/回滚版本、云端文件替换、网络中断与本地当前库保护。
- 云提供商、账户/存储接口、收费和自动备份策略待独立设计，当前不选型。

## C2：多设备端到端加密同步

- 同步剪贴板记录及可选的分组/收藏等元数据，不通过网盘直接同步活跃SQLCipher数据库文件。
- 设计独立同步密钥、设备授权/撤销、新设备加入和恢复凭据；本机DPAPI密钥文件不作为跨设备凭据。
- 设计稳定对象/记录标识、变更序列、删除标记、离线积压、冲突解决、防重复、防回滚与密钥轮换。
- 区分设备私有设置（目录、系统自启动等）与可同步偏好；敏感记录默认策略和到期删除跨设备语义需要单独确认。
- 服务端只保存密文及必要的协议元数据；仍需评估元数据泄露、设备丢失和密码遗失的恢复边界。
- C1可以先实现，C2应独立阶段设计与验收，不用整包覆盖模拟多设备合并。

## P1：macOS适配可行性（待决定）

- 现有主密钥及对象加密、SQLCipher数据结构、密码归档可以作为跨平台基础，实际构建与格式兼容需测试。
- Windows当前使用DPAPI保护主密钥；macOS需要独立的Keychain适配，统一对上提供本机密钥保存/读取/删除接口。Windows的key.bin不能直接搬到macOS解密，应通过密码归档或未来设备授权传递主密钥，再本地重新保护。
- 本地账户锁定/登录、钥匙串权限、备份恢复与安全存储失败语义必须单独验证。
- Windows剪贴板/OLE、键盘钩子、快捷键、窗口/焦点/权限、自启动、文件锁/删除与原子移动等同样需要macOS实现，不能仅替换密钥API便宣称已跨平台。
- 当前本机迁移冷备份含DPAPI key.bin，只承诺原Windows账户；跨平台交换应使用独立密码归档。
