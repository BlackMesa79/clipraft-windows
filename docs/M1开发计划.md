# M1 开发计划

> 日期：2026-11-10
> 状态：2026-11-12，T1～T9 开发、自动回归及最终人工验收通过，M1 完成。既有缺少环境的未测项见人工验收清单。
> 前置：M0 技术验证已通过人工验收（提交 `90d12ff`）
> 范围：设计文档《需求整理与选型评估.md》第二节中尚未完成的 P0 功能，加少量成本低、收益高的 P1 功能
> 不在范围：界面视觉打磨和垂直 3D 滚轮快速面板（M1 全部完成后统一做，规格见设计文档第三节）

## 一、M1 目标

把 M0 原型变成可以日常替代 Ditto/CopyQ 使用的版本：

- 能**找**：搜索、按类型筛选；
- 能**管**：删除、置顶、收藏、分组；
- 能**自动维护**：历史自动清理、开机自启、暂停监听；
- 能**保护隐私**：忽略指定程序，识别敏感内容并自动删除。

界面以"功能可用、结构清晰"为准，不追求美观；前端组件要拆分好，方便之后统一换皮。

## 二、M0 现状（M1 的起点）

| 方面 | 现状 |
|---|---|
| 存储 | `items(id, view JSON, touched)` + `formats(item, name, inline, blob)`。元数据全部塞在 `view` JSON 里，没有独立列，**没有 schema 版本号**。列表固定 `LIMIT 200` |
| 搜索 | 无。内置 SQLCipher 已启用 FTS5（libsqlite3-sys 0.35 的 build.rs 带 `-DSQLITE_ENABLE_FTS5`），可以直接用 |
| 删除 | **没有任何删除功能**，也没有孤儿 blob 回收 |
| 设置 | 无。快捷键等都是源码常量 |
| 前端 | 主窗口和快速面板都在一个 `src/App.vue` 里（约 70+ 行模板），无路由、无状态管理 |
| 后端命令 | `list_items`、`item_detail`、`image_failure_reason`、`panel_state`、`resize_quick`、`last_error`、`frontend_ready`、`thumbnail_loaded`、`preview_loaded`、`paste_item`、`hide_main` |
| 测试 | 172 项（另有 1 项性能测试默认 ignored） |

## 三、任务拆分

依赖关系：

```

               ├── T3 设置系统 ─────────┼── T6 忽略程序与来源记录 ── T7 敏感内容识别
               ├── T4 搜索与筛选        │
```

### T1 存储层演进（前置任务）

**目标**：为后面所有功能打好数据基础，并保证旧数据能平滑升级。

- 引入 schema 版本：用 `PRAGMA user_version` 记录版本号，写一个按版本顺序执行的迁移框架。M0 的库视为版本 0。
- `items` 表新增独立列（从 `view` JSON 迁移出来）：
  - `kind`（text/image/files/rich）、`created`（首次出现时间）、`touched`（已有，最近使用时间）、`size`（所有格式字节数之和）；
  - `pinned`、`favorite`（布尔）、`group_id`（可空）；
  - `source_exe`、`source_title`（可空，T6 填充）；
  - `sensitive`（布尔）、`expires_at`（可空，T7 使用）；
  - `search_text`（用于全文检索的纯文本：文本内容取前若干 KB，文件记录取文件名和路径，图片记录取空或后续 OCR 结果）。
- 新建表：`groups(id, name, sort, created)`、`settings(key, value)`。
- 列表接口改为**分页查询**：`list_items(filter, offset, limit)`，排序规则为"置顶优先，然后按 touched 倒序"。这也是将来滚轮面板"可翻完整个历史"的基础。
- 迁移要求：迁移在一个事务内完成；迁移前自动把 `history.db` 复制一份为 `history.db.bak-v0`（同样是加密文件）；迁移失败要回滚并给出明确提示，绝不删除数据。
- 测试：用 M0 格式的库做迁移测试（可以由测试代码先按旧 schema 建库）；迁移后数据、blob、缩略图完全可读；重复启动不会重复迁移。

### T2 删除与自动清理

- 单条删除、多选批量删除（主窗口中按 Delete 键，或使用右键菜单）。
- 删除时同时删除不再被引用的 blob 文件；启动时做一次**孤儿 blob 扫描**（顺带修复 M0 遗留的 D-10）。
- 自动清理策略，可在设置中配置：
  - 最大条数（默认 1000）、最大占用空间（默认 1 GB）、保留天数（默认 30 天，0 表示不限）；
  - **置顶、收藏、属于某个分组的记录不清理**；
  - 清理时机：启动时执行一次，之后每次保存新记录后检查（要节流，不能每条都全表扫描）。
- 定期或在大量删除后执行 `VACUUM`；`secure_delete=ON` 已经开启，保持不变。
- 测试：各种清理策略的边界、受保护记录不被清理、blob 引用计数正确。

### T3 设置系统

- 后端：`settings` 表 + 带默认值的强类型配置结构；提供 `get_settings` / `update_settings` 命令；修改后立即生效，不需要重启（快捷键除外，见下）。
- 前端：一个最简单的设置页面，可以是主窗口内的一个视图，也可以是独立窗口。分为"通用、历史、隐私、快捷键"几组。
- M1 需要的配置项：
  - 通用：开机自启、启动时暂停监听；
  - 历史：最大条数、最大空间、保留天数；
  - 隐私：忽略程序列表、敏感内容识别开关、敏感内容自动删除时间（默认 10 分钟）；
  - 快捷键：主窗口快捷键、快速面板快捷键，先支持在固定候选中选择即可（例如 Alt+V / Ctrl+Shift+V / Ctrl+\` 等）；修改后重新注册热键，并更新钩子状态机的触发键和修饰键配置（现在是 `hook.rs` 中的常量，需要改为原子变量）；
  - 预留：快速面板可见条数（滚轮面板阶段才会用到，先只存储）。
- 测试：默认值、序列化往返、非法值被拒绝。

### T4 搜索与筛选

- FTS5 虚拟表索引 `search_text`。SQLCipher 会加密整库，FTS 索引同样是加密的。
- 中文分词：FTS5 默认的 unicode61 分词器对中文是按字切分的，效果差。建议使用 `trigram` 分词器（SQLite 3.34+ 内置，可以做子串匹配），对少于 3 个字符的查询回退到 `LIKE`。**先确认内置 SQLCipher 的 SQLite 版本支持 trigram。**
- 主窗口顶部加搜索框：输入时实时过滤（防抖约 150ms）；打开主窗口时焦点自动在搜索框里；方向键仍然可以在列表中移动；Esc 先清空搜索，再按一次才隐藏窗口。
- 类型筛选：全部 / 文本 / 图片 / 文件 / 链接（文本内容整体是一个 URL 的，算作链接）。
- **拼音搜索作为可选扩展**（P1）：保存时额外生成拼音全拼和首字母，写入 `search_text`（可以用 `pinyin` crate）。如果 T4 主体顺利，就一起做。
- 测试：中英文混合、子串、短查询回退、筛选与搜索组合使用、分页。

### T5 置顶、收藏与分组

- 置顶：置顶记录始终排在列表最前面，不参与自动清理。
- 收藏：可以按"只看收藏"筛选，不参与自动清理。
- 分组：
  - 创建、重命名、删除分组（删除分组时，组内记录回到"未分组"，不删除记录）；
  - 把记录移到某个分组，或从分组中移出；
  - 主窗口左侧（或顶部）显示分组列表：全部 / 收藏 / 各个分组；
  - 分组内的记录不参与自动清理。
- 快速面板：M1 先只显示"全部"历史；按 ←/→ 切换分组放到滚轮面板阶段再做。
- 测试：分组增删改、记录移动、删除分组后记录仍在、排序规则正确。

### T6 忽略程序与来源记录

- 采集时记录**剪贴板所有者进程**：用 `GetClipboardOwner` 取得窗口，再找到对应进程的 exe 路径；取不到时，退回到采集时的前台窗口。把结果写入 `source_exe`。
- 忽略列表：按 exe 文件名匹配，不区分大小写，可在设置中增删。默认列表包含常见密码管理器，例如 `KeePass.exe`、`KeePassXC.exe`、`1Password.exe`、`Bitwarden.exe`。
- 主窗口列表和预览区中显示来源程序名称（P1：显示程序图标）。
- 测试：匹配规则（大小写、带路径）、取不到来源时的处理。

### T7 敏感内容识别

- 规则匹配（纯函数，规则写在代码里，用户可以在设置中整体开关）：
  - 常见 token 前缀：`sk-`、`sk-ant-`、`ghp_`、`gho_`、`github_pat_`、`xox[bpa]-`、`AKIA`、`AIza` 等；
  - JWT（`eyJ` 开头，由三段 base64url 组成）；
  - PEM 私钥头（`-----BEGIN ... PRIVATE KEY-----`）；
  - 可选：长度 ≥ 20、不含空白、字符种类高度混杂的高熵字符串（误报风险较高，默认关闭）。
- 命中后：`sensitive = 1`，`expires_at = now + 设置的时长`；列表和预览中脱敏显示（例如 `sk-a••••••••3f`，点击"显示"后才显示原文）；到期后自动删除（复用 T2 的删除逻辑）；以后做同步时不参与同步。
- 用户可以手动标记或取消标记"敏感"。
- 测试：每条规则的正例和反例、普通文本不误报、到期删除。

### T8 托盘与系统集成

- 开机自启：写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（或使用 `tauri-plugin-autostart`），与设置项同步。
- 暂停监听：托盘菜单中切换；暂停时托盘图标和提示文字有所区别；暂停期间不记录任何内容。
- 文件记录失效标注：列表中直接标出"源文件已不存在"（M0 只在粘贴时才报错）。为了避免列表卡顿，检查要在后台进行并缓存结果。
- 托盘菜单：显示/隐藏、暂停/恢复监听、设置、退出。

### T9 回归测试与人工验收

- 交给 Tester：审查 T1～T8 的代码，补充自动化测试（重点是迁移、清理策略、搜索、敏感规则），并检查 M0 已修复的问题有没有复发（修饰键、输入法、Alt 菜单、大图粘贴）。
- 更新 `docs/M0人工验收清单.md`，或新建 `docs/M1人工验收清单.md`，由用户执行。

## 五、每个任务的完成标准（统一）

- `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test` 全部通过，`npm run build` 通过；
- 新的纯逻辑都有单元测试，测试总数只增不减；
- 更新 README（功能、已知限制、验证记录）和人工验收清单；
- Coder 不 commit；主对话复核通过、用户人工验收通过后，由主对话提交。
